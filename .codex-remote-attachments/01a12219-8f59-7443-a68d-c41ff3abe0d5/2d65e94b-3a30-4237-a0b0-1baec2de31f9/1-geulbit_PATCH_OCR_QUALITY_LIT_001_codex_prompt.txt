# PATCH-OCR-QUALITY-LIT-001 — 문학 특화 고정밀 OCR 정확도 개선 통합 실행

## 출발점·범위
AGENTS.md, docs/automation/ACCEPTANCE.md, 현행 Active Plan과 OCR Handoff 최종 source SHA a0df8cf4daa48467de45a95aca7fa9e069bcc6bc595bf86fde8b238a065a2243, 첨부된 geulbit_literary_ocr_debate_decision_v2.txt만 필요한 부분부터 참조한다. 과거 baseline-evidence를 최종 source 위에 덮어쓰지 않는다.

목표: 일반 OCR은 빠르게 유지하면서 시·소설·희곡 중심의 고정밀 자동 초안 정확도와 구조 보존을 실증적으로 개선한다. 표·평가기준은 오인식·오연결 방지만 유지하고 개발 우선순위는 낮춘다.

이번 한 번의 통합 작업에서 조사→원인 분리→구조 복원→선택적 재인식→검수 연결→실자료 쌍체 평가→STAGING 최종 검증·오류 수정까지 진행한다. 내부 단계마다 프롬프트나 재승인을 요청하지 않는다. 운영 배포·운영 DB·실계정 접근은 승인하지 않는다.

## 최소 탐색과 기존 계약
backend/app/services/ocr_pipeline.py의 combine_page, align_lines, compose_draft 및 backend/app/services/ocr_models.py의 recognition_lines, structure, tesseract, region, run부터 검색하여 정의·호출부·관련 테스트만 확인한다. 필요한 때에만 ocr_jobs.py, ocr_api.py, OcrReviewPanel과 관련 테스트를 확인한다.

현재 compose_draft는 줄 텍스트를 '\n'.join()하며 combine_page가 가진 indentPixels/stanzaGapCandidateBefore를 초안에 반영하지 않는다. align_lines는 1:1 박스 겹침 기반이다. 희곡 콜론 뒤 공백의 원인은 아직 확인되지 않았으므로 섣불리 composer 결함으로 단정하지 않는다.

이미 존재하는 Windows Job Object/큐/메모리 상한(일반 프로세스2GiB·잡3GiB, 고정밀 프로세스8GiB·잡9GiB), 중단/재개, 검수·확정 리비전, 일반 OCR, UI 모달·ESC, S4 연결은 재개발하지 않는다. 실제 필요 파일·관련 테스트·UI 소비자만 변경하고 기회주의적 리팩터링을 금지한다.

## 한 번의 통합 구현 및 내부 검증
A. 원인 분리: 기존 고정 합성 OCR 글줄·좌표를 재사용하여 기존 초안 조립 vs 구조 반영 조립을 비교한다. OCR 모델 재실행 없이 시의 물리 행·연·상대 들여쓰기, 산문 물리 줄과 논리 문단, 희곡 화자·대사·지문, 문자·공백 오류의 발생 단계를 추적한다.

B. 구조 보존: 기존 페이지/블록/글줄 ID·box·읽기순서를 단일 기준으로 사용하고 원시 인식·좌표·구조 후보·확정 상태를 구분한다. 장르 프로필은 사용자가 지정할 수 있으면 우선하며 자동 추정이 불확실하면 검수 후보로 둔다. 시의 물리 행은 보존하고 연·들여쓰기와 산문의 논리 문단, 희곡 대사/지문 경계를 원본 좌표에 기반하여 표현한다. 픽셀 간격을 임의 공백 문자 수로 환산하거나 후보 boolean만으로 자동 '\n\n' 삽입하지 않는다. 렌더러/TXT 직렬화/코드포인트 매핑의 영향도 검사한다. 원문이 확인되지 않은 곳은 검수 대상으로 남긴다.

C. 국소 재인식: 오류 정답이 없어도 실행 가능한 트리거(엔진 간 글자·글줄 분할 불일치, 글줄 누락 의심, 비정상 기호·문자 구성, 읽기 순서·화자 경계 후보)를 정의한다. 관련 크롭에서 Tesseract best PSM7(한 줄), PSM6(문단), 필요시 Paddle 재렌더링·재검출을 비교한다. 글줄 대응은 1:1뿐 아니라 1:N/N:1/미대응을 보존하되 불확실한 매칭은 자동 적용하지 않는다. 자동 후보 채택은 개발용 정답에서 성능과 오수정 위험이 입증된 제한 규칙만 사용한다. confidence 직비교·다수결·맞춤법/작가 문체 자동 교정 금지. 효과가 없으면 원문 후보 유지와 검수 표시.

D. VL·자원: VL은 기본 자동 실행하지 않고 사용자 지정 영역에만 기존 Worker/Job Object를 통해 실행한다. 실제 호스트 RAM·가용 커밋·S4 피크를 확인해 입장 조건을 정하되 2/3/6GiB 등 임의의 상한을 새로 강제하지 않는다(기존 VL 피크 약7.83GiB). 여유가 불명확하거나 S4와 충돌하면 VL을 안전하게 대기/거절하고 고정밀 완료라고 오표시하지 않는다. 모델을 상시 로드하거나 전체 페이지에 무조건 VL 실행하지 않는다. 기존 자식 프로세스 종료·재개를 이용해 자원 회수를 확인하고 기존 백업/운영 서비스를 중단하지 않는다.

E. 성능 평가: 기존 합성12페이지·72자 비교는 회귀/원인 분리용이다. 권리·접근이 확보된 실제 시·산문·희곡·해설 자료를 우선해 개발용과 미사용 평가용으로 작품/판본/스캔 그룹 단위 분리한다(탐색 시작안 약40페이지, 개발24/평가16). 외부 AI에 원문 업로드 금지. 평가 전 임계값·선택 정책을 고정하고 동일 PDF를 일반/고정밀로 쌍체 비교한다. 엄격 CER(공백·문장부호·개행 포함), 글자 진단 CER, 시 행/연·상대 들여쓰기, 산문 문단, 희곡 화자/지문, 글줄 누락, 잘못된 자동 변경 수, 검수 수정량·시간, 페이지별 최악값, CPU 시간·작업 전체 커밋/호스트 메모리를 별도 보고한다. 신뢰구간은 작품/문서 군집 단위로 추정하되 표본이 적으면 불확실성을 표시한다. 실제 자료가 없으면 정확도 우위와 CER1% 목표를 PASS라 표시하지 않는다.

F. 최종 검증: 최소 targeted test부터 실행하고 안정 후보에서 관련 OCR 테스트, 일반 OCR 비회귀, 원본·불변 확정본·MATCH_ONLY·IDOR·권한·S4 연결·중단/재개·좌표/Unicode 매핑을 검증한다. STAGING 업로드→자동 초안→원본 검수→불변 확정→자료실·S4 재사용의 전체 흐름을 확인한다. UI 변경 시에만 관련 브라우저/반응형 테스트, 최종 후보에서 typecheck/build를 수행한다. 기존 S4·제품1.0.0 후보·공용 자료 전환·백업과 보호28/고정39는 보존한다. 성공한 장문 테스트 로그·과거 전체 evidence는 재출력하지 않는다.

## 종료 판정과 금지
IMPLEMENTATION, STRUCTURE_QUALITY, PRECISION_ADVANTAGE(실제 미사용 자료 기준 PASS/NO_GAIN/UNVERIFIED_DATA), RESOURCE_SAFETY, STAGING_VERIFIED, OPERATING_APPLIED를 각각 구분한다. 고정밀 자동 초안이 일반보다 실제 문학자료에서 개선되지 않았다면 정확도 우위 PASS 금지; 기능 안전성이 확보되면 구현 결과는 별도 보존한다.

실험에서 반례가 발견되면 승인 범위에서 최소 수정→해당 실패 테스트→관련 회귀 검사 순으로 같은 작업을 계속한다. 파일 수·재시도 횟수를 자의적으로 극소 제한해 새 Phase/Runner 복구 작업을 만들지 않는다. 자료 부재·호스트 리소스가 실제로 불충분하면 안전한 구현 부분을 완료하고 미확인 항목만 남긴다. 완료한 기존 기능은 다시 개발하지 않는다.

운영 DB·서버·마이그레이션·실계정·비밀·원문 권한 확대·모델 원격 전송·자동 commit/push/merge/deploy 금지. 확정 원문을 자동 덮어쓰기 금지. 종료하면 STATUS / CHANGED / RULES / TESTED / RISKS 다섯 항목에 실제 근거만 간략히 보고하고 다음 기능 개발을 시작하지 않는다.
