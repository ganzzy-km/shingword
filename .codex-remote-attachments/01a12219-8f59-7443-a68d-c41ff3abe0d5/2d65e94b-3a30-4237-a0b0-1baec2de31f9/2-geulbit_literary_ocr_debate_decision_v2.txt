코드 재검토에서 확인한 사실
1) backend/app/services/ocr_pipeline.py의 combine_page()는 indentPixels와 stanzaGapCandidateBefore, block, draftLineIndex를 만들지만 compose_draft()는 텍스트를 '\n'.join()으로 결합한다. 구조 정보는 메타데이터에 남지만 초안 문자열에는 반영되지 않는다. 구조 손실의 원인 후보는 명확하나 글줄 분리·문장 내부 공백 소실 등의 개별 원인은 고정된 인식 결과로 분리 실험해야 한다.
2) align_lines()는 영역 겹침 기반의 탐욕적인 1:1 대응 후 비대응 보조 줄을 추가한다. 하나의 줄이 둘로 나뉘는 1:N, 두 줄이 하나가 되는 N:1 사례가 잘못 매칭될 수 있으므로 경계 사례에 한정해 보완한다. 전체 신규 정렬 엔진은 만들지 않는다.
3) ocr_models.py의 고정밀 기본 경로는 PP-StructureV3 + Tesseract 전체 페이지 PSM3 비교; 기본 초안은 Paddle 측 줄 위주이며 선택 영역 Tesseract는 PSM6, VL은 사용자가 선택해 호출한다. PSM6/7 국소 크롭은 도입 후보이지 이미 개선이 증명된 조합이 아니다.
4) ocr_jobs.py에는 Windows Job Object 기반 프로세스/잡 커밋 상한, 프로세스 종료, 진행 상태, 재개 기능이 이미 있다. 일반은 2/3GiB, 고정밀은 8/9GiB, 무거운 OCR 작업은 한 번에 하나다. 새 Job Object/큐는 불필요하다. 그러나 호스트 전체 여유 RAM, S4의 별도 프로세스 피크, VL 공존 안전성은 미측정이다.
5) Poetry·드라마 예시의 엄격 CER는 구조·공백·문자 오류가 합산된다. '여울: 이' 공백 누락을 compose_draft 때문이라고 확정하면 안 된다. 합성 12페이지 지표는 회귀·원인 분리용이며 실제 작품 정확도 보증이 아니다.

다중 AI 합의
A. 구조 복원과 초안 조립 문제를 먼저 측정·수정한다.
B. 원본 이미지 좌표와 원시 인식 결과를 보존하고 장르별 구조 렌더러를 작게 추가한다.
C. 의미적 맞춤법 교정, 임의 공백·문장부호 생성, 서로 다른 모델 confidence의 직접 순위와 다수결은 금지한다.
D. 비교용 모드를 실제 오류를 찾는 트리거 + 국소 재인식 + 개선 검증으로 바꾼다.
E. 실제 문학 자료에서 일반/고정밀의 같은 입력 쌍체 비교, 미사용 평가 자료, 페이지별 및 장르별 보고를 한다.
F. VL은 기본 자동 비활성이고 사용자 선택 영역만 허용, 자원 부족 시 안전하게 스킵한다.

충돌한 의견에 대한 결정
- 'indentPixels를 공백 개수로 바꿔 자동 삽입'은 불채택: 픽셀 폭만으로 원래 공백 개수를 알 수 없다. 상대 들여쓰기는 좌표·표시 레이어에서 보존, TXT 초안은 이미지 근거가 명확한 구분만 적용하고 불명확한 연·문단 경계는 검수 후보로 둔다.
- 'stanzaGapCandidateBefore이면 무조건 두 번 개행'은 불채택: 블록 전환/페이지 위아래 공백을 연으로 오인할 수 있다. 후보와 자동 적용의 임계값·범위를 별도로 검증한다.
- 'VL 상한 2~3GiB, 6GiB' 등의 고정 숫자는 불채택: 기존 VL 단독 시험 약7.83GiB와 모순된다. 호스트 RAM/커밋 여유·S4 사용량·안전 여유를 기준으로 admission control 한다. 수용 가능한 안전 예산이 없으면 실행하지 않는다.
- '새 Windows Job Object/범용 Worker 개발' 불채택: 기존 구현 재사용. 작업 전체 커밋과 호스트 물리 RAM·available commit을 서로 구분해 관측한다.
- '항상 VL을 돌려 고정밀' 불채택: 모델 적재만으로 자원 위험이 크고 자동 결과 개선은 실증되지 않았다.
- '선택적 OCR이 반드시 CER 1% 달성' 불채택: 장기 목표를 유지하고 실제·장르별 성능을 측정한 뒤 보수적으로 판정한다.

통합 패치 개발 방향
I. 고정된 동일 recognition_lines + 현재 composer vs 구조 composer(A/B)로 구조 손실 위치를 원인 분리. 필수: 시 행·연·들여쓰기, 산문 물리 행 vs 논리 문단, 희곡 화자·대사·지문, 좌표·코드포인트 span.
II. 단일 좌표 기반 글줄 원본을 기존 정보에 최소 확장. 장르 프로파일은 사용자의 선택 우선, 자동 판정 불확실하면 후보로 남김. 구조 메타데이터와 TXT/화면 표현을 구분. 시는 물리 행 보존, 문단·연은 근거 불충분 시 제안만.
III. 글줄 미탐지·오인식·읽기 순서 오류를 구분해 관측 가능한 트리거 정의. 독립된 보조 탐지와 1:N/N:1 대응, Tesseract PSM6/7·Paddle 부분 재검출·전처리의 이득을 측정. 신뢰 불충분하면 원본 후보를 유지하고 검수로 보냄.
IV. VL은 수동 선택에만 유지하고 기존 격리 Worker에서 자원 허가 조건에 따라 시행. 중간에 무조건 gc.collect()면 모든 native 메모리가 반환된다는 가정을 하지 않음; OCR 자식 종료를 통한 회수 활용.
V. 실문학 페이지 개발/평가 분리(제안40페이지 중 개발24/미사용16, 동일 작품·판본·스캔 그룹 누출 방지). 확보 자료가 부족하면 실제 정확도 판정은 미검증으로 두되 구현·합성 회귀 검증은 수행.
VI. 최종 STAGING OCR 두 모드 업로드→수정/검수→확정 리비전→S4 재사용, 권한·MATCH_ONLY·원문·불변 리비전·재개, 그리고 S4/OCR 동시 실행의 안전성 검사. 운영 배포 없음.
