# PATCH-OCR-001 — 한국어 원작품·참고자료 고정밀 OCR 통합 구현

## 목적과 실행 방식

기존 OCR-01~05를 개별 승인 작업으로 나누지 않고 하나의 기능 패치로 수행한다.
업로드 → 직접 추출/부분 OCR → 다중 인식·구조 분석 → 차이 검수·재인식 → 확정 리비전 저장 → 기존 분석에서 재사용까지 실제 STAGING에서 연결한다.
조사 보고나 모델 import 성공만으로 종료하지 않는다. 내부 단계마다 짧은 Checkpoint를 남기고 정상 경로에서는 새 사용자 프롬프트 없이 이어간다. 운영 배포는 이번 범위가 아니다.

AGENTS.md, docs/automation/ACCEPTANCE.md, 최신 Active Plan과 검증된 PATCH-LIB-001·PATCH-VERSION-001·PATCH-STAGING-001 receipt의 관련 항목을 참조한다. 이미 완료한 기능을 재구현하지 않는다.
사용자는 개인 프로젝트·지인 시험 사용 기준을 채택했다. 관계 분석용 독립 48편·2인 라벨 부족이나 운영 S4 새 분석 미확인을 OCR 개발의 선행조건으로 삼지 않는다.

## 기준과 보호

- Windows 로컬 CPU, 정확도 우선, 유료 API·외부 OCR 서비스 금지.
- 설치 준비 시 공식 공개 패키지·모델 다운로드는 허용한다. 설치 후 실제 문서 처리는 오프라인이어야 한다.
- 대상: 한국어 원작품·참고자료의 PDF와 인쇄 이미지. 학생 손글씨 인식 제외.
- 기존 S4, R2 DISABLED, 제품 표시 1.0.0, 관리자 공용 전환·공개 중지·MATCH_ONLY 경계 유지.
- 최신 운영 백업·외장 복사·예약 작업·운영 데이터 루트는 수정하지 않는다.
- 기존 운영 DB를 이동·복원·초기화·migration하지 않는다.
- STAGING은 C:\Users\USER\GeulbitStagingData의 기존 환경을 재사용한다. 시험 자료도 임의 삭제하지 않는다.
- UI 전면 개편, 튜토리얼, E01/E03/E05, 기타 원작품 편의 기능은 별도 선택 기능으로 보존한다. 이번 OCR 패치에 무관하게 섞지 않는다.

## 1. 첫 단계에서 작업 범위를 한 번 확정한다

기존 OCR service → 업로드 API 호출부 → 문서/리비전 모델 → 검수 UI → 관련 테스트 순으로 필요한 symbol만 확인한다.
우선 검색 출발점은 backend/app/services/ocr_service.py다. 실제 호출 경로와 실제 클래스·필드가 기준이다. Document, DocumentTextRevision 같은 이름을 존재한다고 가정해 복제하지 않는다.

기존 텍스트 PDF 추출·Tesseract·검수·작업 상태·자료 저장 기능의 유무를 확인하고 재사용 범위를 짧게 기록한 뒤 구현으로 이동한다.

수정 권한의 기능 범위:
- OCR·페이지 렌더링/추출·정렬·문서 구조 모듈
- OCR 전용 로컬 Worker와 기존 작업 수명 관리 연결
- 자료 업로드·검수·확정 API 및 그 화면 소비자
- 기존 문서 리비전과 OCR 부속 결과의 저장 연결
- 위 기능의 테스트, 격리 의존성/모델 설정, 최소 설치·사용 기록

실제 경로를 확인한 파일 allowlist와 역할을 기존 패치 실행 계약에 한 번 등록한다. 임의의 2~3개 파일 상한으로 필요한 API·UI·테스트를 누락하거나 복제하지 않는다. 무관한 코드·Runner·인증·분석 엔진 변경은 허용하지 않는다. 코드 범위가 승인된 기능 밖으로 나갈 때만 별도 사유를 보고한다.

기존 리비전·작업 저장을 우선한다. 지속 상태를 안전하게 저장하려면 추가 스키마가 불가피한 경우에만 최소 additive migration을 작성하고 격리 STAGING에서 검증할 수 있다. 실제 현재 migration lineage를 확인하여 번호를 결정한다. 기존 행·리비전·식별자 변경, 테스트 DB 재초기화, 운영 migration은 금지한다. migration이 있으면 운영 적용의 별도 요구사항으로 남긴다.

기존 S3/S4에서는 이미 구현해야 할 기능과 과거의 '없어야 함' 테스트가 충돌한 바 있다. 이번에도 테스트를 보안·불변성 계약과 과거 구현 범위 검사로 구분한다. 이 명세와 직접 충돌하는 범위 검사는 원본 보존·명시적 변경 사유·강화된 대체 검사 후 개정할 수 있다. 모델 결과에 맞춰 정답이나 평가 기준을 바꾸는 것은 금지한다.

## 2. 포함할 기술 — 실제 실행 가능한 구현

A. PDF 처리
- 기존 처리기의 추출·렌더링을 재사용하되 코드·배포 의존성 라이선스 확인.
- PyMuPDF 사용 조건과 양립 여부를 확인하지 못하면 OCR 경계에서 pypdfium2 등 적합한 대안을 검토한다. 두 처리기를 반드시 모두 설치할 필요는 없다. 기존 PDF 전체 기능을 무관하게 교체하지 않는다.

B. PaddleOCR
- 한국어 인식기 korean_PP-OCRv5_mobile_rec를 명시적으로 선택한다.
- 검출기는 PP-OCRv5_server_det를 우선 후보로 사용하고 실제 CPU 비용·한국어 검출 결과를 확인한다.
- PP-OCRv5라는 이름만으로 한국어 인식이 설정됐다고 간주하지 않는다. 최신 다른 세대로 자동 변경하지 않는다.

C. Tesseract
- 기존 Tesseract 5와 kor+eng, tessdata_best를 사용한다. 실제 버전·언어 파일·경로 확인.
- tessdata_best의 LSTM 실행 방식(--oem 1), 적절한 페이지/블록/줄 분할 옵션을 실제 비교한다. 운영 Tesseract 설치를 무단 교체하지 않는다.

D. PP-StructureV3
- 레이아웃·읽기 순서·제목·본문·각주·표 구분을 실제 처리에 연결한다.
- 표 영역·행열과 셀의 텍스트 연결을 지원 범위에서 보존한다. 불명확한 셀 구조는 검수 대상으로 남긴다.
- 기존 Paddle OCR 결과와 중복 전체 인식을 피하고 구성 모듈을 선택해 재사용한다. 내장 OCR을 사용할 때도 중국어·영어 기본값이 아니라 고정한 한국어 인식기를 명시한다.
- 공식 기본 Markdown 변환이 각주·페이지 번호·머리말 등을 제외할 수 있으므로 원시 구조 정보를 기준으로 보존한다.
- 도표 의미 해설, 문서 번역, 수식 전용 모델·도장 인식 등 요청되지 않은 모듈의 일괄 설치는 하지 않는다. 그림·수식 영역은 이미지/좌표를 보존하며 미전사 영역을 숨기지 않는다.

E. PaddleOCR-VL
- 이번 패치의 구현 대상이다. TODO, 가짜 호출, 클래스 껍데기만 만들고 완료 처리하지 않는다.
- 사용자 선택 영역 또는 미해결 OCR 영역을 실제 로컬 CPU 모델로 재인식하고 결과를 비교·채택할 수 있게 연결한다.
- 공식 CPU·Windows 호환 경로와 특정 모델/가중치 리비전을 고정한다. Paddle/Transformers 등 가능한 로컬 경로 중 호환 조합 하나를 선택한다. 공개 inference 서버나 vLLM·Docker·WSL을 필수로 추가하지 않는다.
- 문서 전체 자동 상시 실행이 아니라 선택적 '정밀 재인식' 경로다. 최초에는 사용자가 명시적으로 요청한 영역에서 실행한다. 모델은 필요할 때 로드하고 자원을 회수한다.
- 전체 페이지 레이아웃+VLM 파이프라인과 잘라낸 영역의 VLM 인식은 구분한다. 영역 인식을 전체 파이프라인의 공식 성능으로 주장하지 않는다.
- 재인식 결과는 대안 초안이며 원문 정답으로 자동 확정하지 않는다.

모든 코드·선택 가중치·직접 배포 의존성의 라이선스/notice, 정확한 버전, 출처, SHA, 필요한 디스크를 하나의 모델 설치 manifest에 기록한다. '무료 API'로 로컬 모델을 대체하지 않는다.
실제 장비에서 VL 또는 다른 모델이 실행 불가하면 오류·메모리·시도한 지원 조합을 남기고 해당 구성만 UNAVAILABLE로 표시한다. 안전하게 진행 가능한 나머지 기능은 완료하되 '요청한 기술 전부 구현 완료'라고 보고하지 않는다.

## 3. 하나의 원문 처리 파이프라인

1) 기존 업로드 형식·용량·페이지·사용자 권한 검사와 안전한 저장 방식을 재사용한다. PDF 암호·손상·초대형 이미지에는 명시적인 실패를 반환하고 원본을 보존한다.
2) 페이지/영역별로 텍스트 레이어의 내용·중복·문자 깨짐·배치·이미지 영역을 살펴 직접 추출/부분 OCR/전체 OCR/빈 페이지를 구분한다. 문자열이 존재한다는 조건만으로 정상 판정하지 않는다.
3) 정상 텍스트는 불필요하게 OCR로 대체하지 않는다. 혼합 페이지는 OCR과 텍스트 영역을 대응해 중복 삽입을 막는다.
4) OCR 렌더링은 300 DPI에서 시작하되 영역 재처리에서만 검증된 확대·회전·기울기 보정을 선택한다. 원본 파일은 변경하지 않는다.
5) 원본 페이지의 좌표계·회전·CropBox와 이미지 변환을 기록하고 영역·글줄을 원문 위치에 대응한다.
6) Paddle와 Tesseract 결과를 같은 페이지·영역·글줄 기준으로 정렬한다. Tesseract는 Paddle가 잘라낸 글줄만 인식하지 않도록 별도 페이지/블록 검출 결과도 사용해 누락 후보를 찾는다.
7) 문자 불일치, 한쪽만 존재하는 글줄, 읽기 순서 문제를 구분한다. 단순 다수결이나 엔진 confidence 값의 직접 대소 비교로 정답을 결정하지 않는다.
8) 불일치 영역만 한정된 설정으로 재인식하고 필요 시 실제 VL 경로를 사용한다. 자동 재시도 횟수와 총 처리 예산을 유한하게 설정한다. 무제한 DPI·모델 조합 탐색 금지.
9) 원작품의 표기·띄어쓰기·인용부호·문장부호를 보존한다. 맞춤법 교정·작가 문체 변경·생성형 문장 보완 금지.
10) 시의 물리적 글줄·들여쓰기·연 후보를 보존하고 자동 산문 재배치를 하지 않는다. 일반 산문의 줄바꿈 처리와 분리한다. 불확실한 구조는 UI에서 수정 가능해야 한다.

## 4. Worker와 저장 수명

- Flask 요청은 작업 등록·상태 조회·검수만 담당하고 추론은 OCR 전용 로컬 프로세스에서 수행한다. 기존 작업 관리가 있으면 재사용한다.
- 기본 무거운 작업 동시 실행 1개. 페이지 순차 처리, 제한된 모델 로딩·스레드·페이지 수·픽셀 수·시간·메모리 예산을 설정한다. 실제 장비를 확인해 값을 기록하고 자원 고갈을 검사한다.
- 실행 프로세스만 분리했다고 웹 서비스 보호가 완료됐다고 간주하지 않는다. STAGING 에세이 저장·분석과 함께 실행해 응답·오류·메모리를 확인한다.
- 추론 중 DB 쓰기 트랜잭션을 계속 열지 않는다. 페이지 결과를 원자적으로 확정한 뒤 상태를 갱신한다.
- 원본 hash, 소유권, 입력 revision, 모델·옵션 fingerprint로 캐시를 구분한다. 다른 사용자의 원문을 hash만으로 조회·재사용하지 않는다.
- 이미 확정된 동일 리비전은 재OCR 없이 재사용한다. 새 모델 비교는 새 draft/job에서 실행하며 과거 확정본을 덮어쓰지 않는다.
- 페이지 완료 상태, 실패·재시도·취소를 저장한다. Worker 강제 종료 후 완료 페이지 재사용, 중단 페이지 재개, 중복 실행의 idempotency를 검사한다.
- 취소·기한 만료·자료 삭제·권한 철회 후 도착한 결과가 리비전을 확정하지 못하게 재검사한다.
- 원본, 엔진별 원시 결과, 검수 draft, 확정 텍스트, 구조 JSON, 모델 manifest를 구분한다. 확정은 기존 리비전 절차로 수행하며 version 충돌을 탐지한다.
- OCR 파생 파일도 기존 소유권·보관·삭제 정책에 연결하고 실패 임시 파일의 크기·정리 범위를 제한한다. 기존 백업 대상 파일 구조를 재사용하되 외장 예약 작업 자체는 수정하지 않는다.
- UTF-8 TXT와 페이지 구조 JSON을 출력한다. 분석용 NFC/LF 텍스트와 원시 표기는 구분하고 코드포인트 구간 매핑을 유지한다. 사용자 수정 후 매핑이 불분명하면 연결을 추측하지 않는다.
- OCR 초안을 확정하지 않은 새 자료는 기존 S4 분석의 기준 원문으로 사용하지 않는다. 이미 확정돼 정상 사용 중인 기존 자료의 흐름은 유지한다.

## 5. 검수 UI와 자료실 연결

기존 업로드·자료 상세·추출 텍스트 검수 화면을 우선 확장한다. 별도 대형 관리 시스템이나 무관한 UI 재설계는 하지 않는다.

필수 실제 동작:
- 원본 페이지/영역과 OCR 텍스트를 나란히 확인
- 페이지·글줄 이동, 불일치·누락 후보 표시와 필터
- 원문 확인 후 텍스트·행/연·읽기 순서 수정
- 선택 영역만 재인식, 엔진별 대안 비교, 선택한 결과만 draft에 반영
- 임시 저장, 이어서 검수, 확정, 권한 있는 TXT·구조 JSON 다운로드
- 실제 작업의 페이지 진행·실패·재시도·취소 상태 표시
- 확정 리비전을 자료실에서 선택해 S4 분석에 사용하고 다시 조회

자료 소유자 또는 기존 권한상 허용된 검수자만 접근한다. 관리자가 타인 개인 자료를 무조건 열람하게 하지 않는다. MATCH_ONLY의 텍스트·이미지 crop·OCR 후보·다운로드·로그에도 기존 노출 제한을 적용한다.
OCR 완료나 검수 확정만으로 자료를 공용으로 바꾸지 않는다. PATCH-LIB-001의 공개/중지와 작성자 저장 분석 조회 계약을 보존한다.
문서 텍스트와 모델 출력은 데이터로 취급한다. 지시문 실행이나 임의 HTML/script 렌더링을 금지한다.
불필요한 면책 팝업·감성 문구를 추가하지 않는다.

## 6. 동일 패치의 연속 실행 순서

A. 기존 경로·환경·라이선스·변경 Scope 확인, 대표 입력의 원본 기준 고정
B. 격리 OCR 환경 설치, 실제 모델별 CPU smoke, 로컬 경로·버전 고정
C. 추출·구조·다중 OCR·비교·재인식·Worker·저장 연결
D. 실제 검수 UI·확정 리비전·S4 재사용 연결
E. 통합 동작·원문 정확도·자원·권한 검증, 적용 가능한 후보와 복귀 정보 보관

위 단계는 별도 패치나 사용자 재승인 단계가 아니다. 단계별 기록은 STATUS/CHANGED/RULES/TESTED/RISKS와 다음 단계 참조만 남긴다. 재시작 시 완료한 코드·모델 다운로드·유효한 테스트를 반복하지 않는다.
허용 범위 안의 설치·테스트·구현 오류는 최소 수정 후 실패 테스트부터 재검증한다. 예상 RED, 테스트 harness 오류, 모델 실행 불가, 실제 제품 회귀를 구분한다. 안전·권한·데이터 무결성 위반은 즉시 해당 작업을 멈춘다. 같은 실패에 효과 없는 수정을 반복하거나 새 Runner 복구 체계를 만들지 않는다.
데이터·모델 다운로드 부재는 영향을 받는 검사만 미완료로 기록한다. 가능한 구현을 모두 남기고 의존성으로 불가능한 부분을 구체적으로 보고한다. 누락된 기능을 완료 처리하지 않는다.

## 7. 최소 검증과 합격 기준

자료는 실제 제공된 한국어 원작품·참고자료에서 확보 가능한 것을 우선한다. 기존의 합성 에세이 24편을 스캔 자료나 독립 OCR 정답으로 바꾸어 부르지 않는다.
처음 목표는 약 12페이지다: 정상 텍스트 2, 산문 스캔 2, 시 2, 희곡 2, 표/각주/다단 2, 혼합/왜곡 2. 같은 문서 변형은 같은 그룹으로 세고 일부 문서의 약 4페이지는 최종 비교 전까지 규칙 조정에 사용하지 않는다.
실자료 부족 시 저작권 문제가 없는 합성 페이지로 기능 테스트를 계속할 수 있다. SYNTHETIC로 표시하고 실제 자료 정확도는 NOT_MEASURED로 남긴다. 별도 사람 2명 라벨을 모든 개발의 차단 조건으로 요구하지 않는다.

평가 정답은 원본 이미지와 사람이 대조한 텍스트·행·구조다. 현재 OCR 결과를 그대로 정답으로 복사하지 않는다.
비교: 현재 Tesseract 기준, 한국어 Paddle 단독, 두 엔진 비교/결합, 구조 분석 포함, 필요한 정밀 재인식 포함. 구성을 바꿔도 동일 입력과 동일 평가 정의를 사용한다.

측정:
- 공백·문장부호를 포함한 CER와 페이지별 오류/실패; 보조 정규화 지표는 별도
- 글줄 누락, 읽기 순서, 시의 행·연, 인용 구간 완전 일치
- 실제 수행한 수동 수정량, 페이지 처리시간, 초기 모델 로딩, Worker+웹 메모리
- 원시 OCR 출력과 사람 수정 후 확정본의 품질을 분리
CER 1% 이하는 선명한 인쇄 자료의 목표이며 사전 보장이나 임의 PASS 근거가 아니다. 정답이 없으면 정확도 수치를 만들지 않는다. 엔진 두 개의 일치율을 정확도라고 부르지 않는다.

필수 기능 검사:
1. 정상 텍스트는 OCR 호출 없이 추출하고 혼합 입력에 본문 중복이 없음.
2. 한국어 Paddle, Tesseract, 구조 분석, VL 선택 재인식이 각각 실제 CPU에서 적어도 대표 입력으로 실행됨. 모의 테스트만 통과한 구성은 별도 표시.
3. 네트워크가 없는 OCR 전용 프로세스에서 로컬 모델 초기화·추론·재개가 가능함. 운영 네트워크는 끄지 않는다.
4. 글줄·페이지·좌표 변환·UTF-8·시 행/연의 사전 fixture 검사 통과.
5. 처리 중 종료/재시작, 실패/취소, 중복 요청에서 완료 결과와 기존 데이터를 보존함.
6. 실제 STAGING 업로드 → 검수 → 확정 → TXT/JSON → 자료실 선택 → S4 새 분석 → 저장·재조회가 연결됨. 재사용 시 OCR 호출 0인지 확인.
7. 기존 확정 리비전과 과거 분석을 덮어쓰지 않고 개인/공용·MATCH_ONLY 경계 유지.
8. OCR 실행 중 일반 에세이 사용과 메모리 한도 동작 확인. 장기 30분 soak를 기본 요구하지 않음.
9. 신규 targeted tests와 영향받는 업로드·리비전·권한·공용 자료 테스트 통과. 최종 UI 후보에서 typecheck/build 1회와 필요한 실제 STAGING 화면 검사.
10. 수정하지 않은 S4 전체 테스트·관계 57건·외장 백업 검증은 유효한 해시 연결을 확인해 재사용. 무관한 전체 재검사 금지.

추가 엔진이 자동 채택 정확도를 악화시키면 기능을 삭제해 범위에서 숨기지 말고 비교/수동 재인식 도구로 유지한다. 기본 자동 경로의 채택은 실측 근거가 있을 때만 변경한다.

## 8. 완료·산출물

한 개의 최종 Handoff에 실제 diff·버전/모델 manifest·실행 명령·설치/오프라인 사용법·평가 요약·알려진 한계·운영 적용/복귀 요구사항을 담는다. 사용자 원작품 전문·비밀값을 Handoff에 무단 포함하지 않는다. 대형 모델은 필요 없이 ZIP에 중복 포함하지 말고 검증 가능한 로컬 설치 패키지/경로·해시로 관리한다.

상태를 구분한다:
IMPLEMENTATION: PASS / PARTIAL / BLOCKED
CORE_OCR: PASS / ...
STRUCTURE_AND_COMPARISON: PASS / ...
VL_REGION_RECOGNITION: PASS / UNAVAILABLE / NOT_VERIFIED
REVIEW_REVISION_FLOW: PASS / ...
OFFLINE_CPU_VERIFIED: true / false
QUALITY_MEASUREMENT: 수치·자료 범위 또는 NOT_MEASURED
STAGING_VERIFIED: true / false
OPERATING_APPLIED: false

전부 구현한 것으로 보고하려면 요청된 구성의 실제 실행과 종단 흐름이 확인돼야 한다. stub나 화면 버튼만 만든 기능은 PASS가 아니다. 일부의 실제 실행이 불가능해도 나머지 결과는 보존하고 미완료 항목만 정확히 구분한다.
검증 후 이번 작업이 띄운 STAGING/Worker만 안전하게 종료하고 이전 시험 런타임을 필요 시 복원한다. 사용자의 기존 시험 데이터와 운영 서비스는 보존한다.

승인 없는 운영 적용·운영 migration·라이브 의존성 업그레이드·commit/push/merge/deploy 금지. 운영 적용은 최종 후보를 검토한 뒤 별도 수행한다.
최종 응답은 STATUS / CHANGED / RULES / TESTED / RISKS 다섯 항목만 사용하고 실제 검증 범위·미완료·다음 적용 조건을 짧게 보고한다. 목표 달성 후 무관한 기능을 계속 구현하지 않는다.
