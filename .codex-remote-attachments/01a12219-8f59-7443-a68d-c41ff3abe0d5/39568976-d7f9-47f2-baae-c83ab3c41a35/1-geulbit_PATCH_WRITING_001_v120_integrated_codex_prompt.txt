# PATCH-WRITING-001 — 글빛 1.2.0 통합 글쓰기·원작품 활용·UI 개발

## 목표와 실행 권한

현재 정상 운영 중인 글빛 1.1.0의 S4 분석·일반/고정밀 OCR·자료실·로그인 기능을 재사용하여, 아래 승인된 UI·원작품 활용·논증 기능 전부를 **한 번의 연속된 개발 작업**으로 구현한다. 조사 → 필요한 설계 결정 → 백엔드·프론트엔드·저장·권한 → 연결 → 결함 수정 → 관련 테스트 → 실제 STAGING 종단 검증 → 1.2.0 출시 후보 및 인계까지 진행한다. 내부 단계마다 사용자에게 새 프롬프트나 승인을 요구하지 않는다. 한두 파일의 오류를 수정하려고 새 Phase·Runner·복구 엔진을 만들지 않는다. 작업 시간에 별도의 총량 제한을 두지 않되, 개별 작업의 타임아웃·메모리·서비스 안전 가드는 유지한다.

**이번 승인은 격리 개발·STAGING 검증까지다. 운영 서버 중지·재시작·배포, 운영 DB 마이그레이션·복원, commit/push/merge는 승인하지 않는다.**

## 최신 기준과 탐색 최소화

- AGENTS.md, docs/automation/ACCEPTANCE.md, 최신 Active Plan과 `PATCH-INTEGRATED-S4-OCR-RELEASE`의 README-final/checkpoint/product-inventory/무결성 receipt만 필요한 범위로 읽는다. 과거 거대 보고서, EVIDENCE 전체나 저장소 전체를 다시 조사하지 않는다.
- 운영 글빛 1.1.0은 S4·두 OCR 모드·확정 리비전·Google 로그인·자료실·백업이 이미 동작하며 실제 운영 후검증을 마친 상태다. 제공된 마지막 운영 Handoff의 source SHA `c07cd9ff9205e596694346db221a395b2624c6a267518fbc43b926251d20dca1`은 **대조 기준**일 뿐이다. 현재 파일·실행 환경·후보가 그 해시와 다른 경우 이유를 먼저 확인하고 임의로 되돌리거나 덮어쓰지 않는다.
- 운영 DB는 `C:\Users\USER\GeulbitData\db\geulbit.sqlite3`이며 기존 schema `0004_user_annotations`. STAGING 루트는 `C:\Users\USER\GeulbitStagingData`, 전용 서버는 `https://localhost:8786`. 현재 운영 서버·ngrok/Google 설정·외장 HDD 복사·예약 작업을 변경하지 않는다.
- 기존 구현 탐색은 기능별 symbol → 정의 → API/화면 소비자 → 기존 모델·migration → 관련 테스트 순서로 수행한다. `quote_card`, `user_annotations`, `writing_version`, 원문·문서 리비전, 자료실/rights, workspace setting, S4 자동 관계·OCR 확정 텍스트의 **기존 단일 원본**을 최우선 재사용한다. 정확한 심볼·테이블·UI 경로는 실제 저장소에서 확인한다. 원문 기반 영구 자료·주석·관계의 병렬 저장 엔진을 만들지 않는다.
- 기존 1.1.0 제품 기능과 개발 중/검증 후보의 차이를 현재 파일 SHA로 확인한다. 이전 격리 후보를 운영본에 통째로 복사하지 않는다. 이미 구현된 항목은 신규로 만들지 말고 이번 요구사항과의 동작 차이만 보완한다.
- 수정 범위는 업무에 직접 필요한 API·UI·모델/버전드 migration·사용자 설정·테스트·관련 소비자까지 초기 탐색 후 한 번에 합리적으로 등록한다. 인위적으로 파일 2~3개로 제한하거나 사소한 추가 승인 때문에 중단하지 않는다. 관련 없는 리팩터링, OCR·S4 규칙 변경, 새 프레임워크 도입은 금지한다.

## A. UI·최초 사용 경험 — 모두 구현

- 장식적인 환영·감성·중복 안내 문구 및 의미 없는 확인 팝업을 줄이고, 본문·피드백·원작품 작업의 시각적 위계를 정리한다. 시험판·정확도 면책·성적 향상 안내문은 새로 추가하지 않는다. 저장 중/완료/실패, 분석 중/완료, STALE, 권한 제한, 처리 중 상태 등 **실제 사용에 필요한 문구와 법적 동의**는 보존한다.
- 처음 가입·첫 접속한 사용자에게 실제 UI 요소에 연결된 4단계 튜토리얼을 표시한다: 글 입력/가져오기 → 선택적 원작품 선택 → 분석 실행 → 실제 결과 화면의 피드백 보기. 다음/이전/건너뛰기/완료/도움말에서 다시 보기, 계정별 완료 상태 저장, 모달 초점·키보드·ESC·모바일 대응. 기존 사용자를 갑자기 막거나 가짜 분석을 생성하지 않는다. 결과가 없으면 해당 단계는 결과 화면에 도달했을 때만 표시한다.
- C01 집중 편집 모드(기존 책·서재 보기로 복귀), C02 본문 크기·줄 간격·본문 폭 조절과 재접속 복원, C03 피드백 유형/기존 처리 상태별 필터·정렬, C04 선택한 피드백·관계 중심 강조, C05 문단 목차·본문 위치 이동 및 편집 후 갱신을 구현한다. 390px 등 좁은 화면에서는 본문·자료·메모를 전환하며 키보드·화면낭독기 기본 접근성을 유지한다. C06 읽어주기는 제외한다.
- 기존 OCR 선택 모달, X·ESC 단계별 뒤로 가기, 더티 상태 보호, 두 테마를 깨지 않는다. 한 번의 ESC로 한 단계만 돌아가며 저장되지 않은 글을 잃지 않도록 한다.

## B. 원작품·참고자료 도구 — D01~D04, D06~D14 전부 구현

- D01 사용자별 즐겨찾기·최근 사용 자료. D02 제목·작가·장르·개인/공용·이용 범위 검색/필터. 모두 조회 권한을 서버에서 먼저 적용해 숨겨진 자료의 존재·제목도 노출하지 않는다.
- D03 인용·장면 카드: 기존 카드·주석을 확장해 작품/문서의 **불변 리비전**, 원문 좌표/구간, 직접 인용인지 장면 요약인지, 사용자 해석 메모를 연결한다.
- D04 허용된 원문과 에세이를 데스크톱에서 나란히 보기, 작은 화면은 탭/패널 전환. 독립 스크롤·선택 위치 유지.
- D06 일반 사용자 공용 자료 등록 요청: 소유자의 특정 자료·리비전에 대한 명시적 공개 신청과 권리 근거 → PENDING/APPROVED/REJECTED/WITHDRAWN 관리 → 권한 있는 관리자의 검토/승인·거절 → 공개 범위 갱신. **기존 '관리자 본인 소유 자료만 직접 공개 전환' 계약을 우회하지 않는다.** 필요 시 신청자가 해당 특정 리비전에 대해 명시적으로 위임한 서버측 승인 경로를 기존 rights 모델에 최소 확장하되 다른 개인 자료를 관리자가 임의 공개하지 못한다. 검증할 수 없는 권한·권리 정보나 복수 판본의 모호성은 안전하게 보류한다. 요청 취소·중복 승인·동시 신청, 공개 중지·기존 작성자 분석 보존을 검사한다.
- D07 작품·참고자료 문맥 검색(KWIC)과 앞뒤 문맥·원문 위치 이동. D08 원문 구절 ↔ 에세이 해당 근거·문단의 양방향 이동·위치 복원. 둘 다 sourceId/revisionId/span과 실제 원문 대응을 확인하고 다른 판본으로 추정 연결하지 않는다.
- D09 작품별 개인 노트(인물·이미지·갈등·질문): 아래 E03 메모의 필터·분류 UI로 제공하고 중복 저장소를 만들지 않는다.
- D10 한 작품의 여러 떨어진 구절 또는 권한 있는 다른 작품의 구절을 나란히 비교, 원문 위치·문맥 표시. D11 주장별 지지/다른 해석/반대/미분류 근거 묶음(사용자 분류이며 자동 채점·자동 확정 금지).
- D12 `원작품/참고 해설/내 해석` 출처 유형을 구분·표시. D13 **직접 인용**으로 지정한 문장만 고정된 판본과 Unicode·공백·문장부호 차이 표시, 요약/바꿔쓰기는 오인용으로 판단하지 않는다. D14 작품/판본별 읽던 위치·열었던 메모·본문 작업 맥락 복원, 권한 상실 시 비공개 원문 복원 금지.
- D05 OCR 텍스트 검수는 현재 운영 1.1.0의 OCR 기능이다. 다시 구현하지 않고 권한·확정 판본 인터페이스만 연동한다. OCR 모델·Worker·영역 재인식 코드를 수정하지 않는다.

## C. 에세이 논증 — E01·E03·E05 모두 구현

- E01 자동 후보가 없는 임의의 사용자 선택 구간도 주장·근거로 직접 지정하고 다대다 관계를 만들고 변경·해제한다. 자동 S4 APPROVED/REVIEW 및 S4 snapshot과는 독립된 `USER_DEFINED` 출처로 저장·표시한다. 본문 수정, 버전 전환, 자동 재분석 후 관계의 대상이 달라질 경우 확실한 anchor만 재연결하고 모호하면 `NEEDS_REVIEW`/STALE로 남긴다. 자동 분석이 사용자 지정 관계를 덮어쓰거나 사용자 관계를 자동 승인으로 취급하지 않는다.
- E03 `근거 → 내 해석 → 주장`을 부분 입력만으로도 저장할 수 있는 메모/장면 카드. 원문·판본·위치, 에세이 문단·버전, D03/D09/D11과 E01 관계에 연결하고 개인 자료로 보관한다. 자동 생성된 해석이나 검증된 문학적 정답으로 표시하지 않는다.
- E05 내 에세이 핵심어 검색·강조, 문단별 위치·문맥 이동, 복수 핵심어 지원. 정확 문자열 검색 기본, 필요 시 기존 형태소 분석 도구로 활용형 포함 옵션을 제공하되 자동으로 의미상 같은 단어라 주장하지 않는다. 단어 반복 자체를 오류로 판단하지 않는다.

## 공통 저장·일관성·자료 보호 계약

1. `writing_version`, canonical confirmed document text revision, 자료 권한과 existing annotation/quote-card를 단일 원본으로 이용한다. 직접 연결·메모는 자동 S4 결과 및 OCR 원본과 독립된 사용자 메타데이터로 관리한다. 필요할 때만 기존 schema 버전 체계의 **추가 migration을 STAGING에서만** 구성하고 격리 복사본의 forward/backward 데이터 보존 및 운영 적용 시 호환성·복귀 전략을 기록한다. 운영 DB 0004를 직접 변경하거나 이전 판본을 파괴하지 않는다.
2. 모든 구간 링크는 글/문서 ID, 불변 리비전 또는 글 버전 ID, 실제 span/anchor, 원문 일치 근거를 저장·검증한다. Python codepoint ↔ JavaScript UTF-16, NFC/LF, 이모지·결합 문자, 중복 구절, 글 수정·삭제, 판본 교체, 충돌/동시 편집을 검사한다. 재연결 불확실성을 임의 추정하여 다른 구절에 붙이지 않는다.
3. 문서 전체·검색 snippet·구절 비교·메모/카드·출처 이동·인용 차이·API/PDF/TXT/JSON/캐시·UI 어느 경로에서도 기존 `MATCH_ONLY`, VIEW/DOWNLOAD와 개인·공용·작성자 권한을 유지한다. 볼 수 없는 원문이나 크롭, 글줄, excerpt를 새 화면/API로 우회 제공하지 않는다. 관리자 기능은 서버에서 검사하고 IDOR/CSRF/XSS, 접근 범위·공개 중지 후 재조회·철회 정책을 함께 검증한다.
4. 자료를 공용으로 전환해도 개인 메모·독서 기록·에세이·직접 관계가 자동 공개되지 않는다. 원문 직접 인용과 내 장면 요약·참고 해설을 혼동하지 않는다. 현재 확정 원문/ OCR 리비전/과거 S4 분석을 덮어쓰지 않는다.
5. 테스트 전용 로그인, `__staging__` 경로·합성 데이터·포트·비밀값·데이터 루트 설정은 운영 빌드/설정에 섞이지 않는다. 운영 S4/OCR, 현재 백업·외장 예약 작업, protected 28/fixed 39, R2 DISABLED 및 과거 Checkpoint를 보존한다.

## 진행·검증을 한 번에 마치기

- **시작:** 실제 운영 1.1.0과 현재 격리 후보, STAGING 기존 DB 상태를 읽기 전용 비교한다. 기능별 기존 구현/수정 대상/간접 소비자를 목록으로 고정한다. 큰 설계 보고서는 만들지 않는다. S4/OCR 기능은 해시·관련 계약 재사용만 하고 전체 재개발하지 않는다.
- **구현:** 기존 저장·화면 구조의 UI/API/DB 최소 확장과 필요한 버전드 migration을 연계하여 위 기능 모두 구현한다. 중간 오류는 가장 작은 실패 테스트부터 수정·재검증한다. 다른 Phase의 기능을 자동 추가하거나 테스트 기대값을 실패에 맞춰 완화하지 않는다.
- **부분 검증:** 관련 UI/백엔드 권한·문서·주석·연결·저장·이탈 보호 targeted test 중심으로 검증한다. 전체 빌드·E2E·전체 OCR·57조건 재생을 매 수정마다 실행하지 않는다.
- **최종 후보 통합 검증:** 동일 코드·migration·설정으로 typecheck, production build, 변경 영향 관련 suite와 필요 안전 회귀 검사를 실행한다. 실제 STAGING API+브라우저에서 학생 A/B, 일반 신청자, 관리자 역할로 아래 흐름을 실행한다: 첫 접속 안내(다시 보기/건너뛰기 포함) → 원작품 검색·즐겨찾기·구절 비교 → 글 작성·S4 분석 → 원작품/에세이 왕복 → D03/E03 메모와 작품별 노트 → E01 직접 연결 → E05 검색 → 본문 수정 후 연결 STALE·재확인 → 인용 대조 → 공용 등록 요청·관리자 승인/거절/공개 중지 → 재기동·자료 재조회. 모든 선택 카드/버튼은 실제 API를 호출하고 저장 후 재조회돼야 한다.
- **반례 검증:** 다른 학생의 개인 글/메모·공용 전환 접근, MATCH_ONLY 우회 검색/인용/내보내기, 취소·철회 후 접근, 서로 다른 작품의 동일 문구, Unicode 오프셋, 중복 클릭·경합·CSRF·XSS, 로그인 세션 차이, 직접 URL 접근, 오류·저장 실패·ESC 동작. 원래 잘 동작하던 저장·OCR 확정·S4·PDF 출력·외장 백업의 변경 없는 경로는 관련 SHA receipt와 최소 통합 smoke로 확인한다.
- **화면 검증:** 두 테마와 1440/820/390px에서 실제 화면 확인. 중요 UI 요소의 키보드 조작·초점 복원·수평 넘침·문구 정리 후 상태 설명을 확인한다. 모바일 실기기를 직접 확인하지 못하면 별도로 UNVERIFIED로 기록한다.
- **마무리:** 제품 표시 버전을 기존 `package.json.version` 단일 원본에서 **1.2.0 후보**로 갱신하되, 내부 S4/R0/R1 스냅샷·OCR 모델·DB schema 버전은 제품 버전과 혼동하지 않는다. 버전 표시는 STAGING에서 확인하고 1.1.0 운영 사이트를 자동 갱신하지 않는다. STAGING 서버를 자신이 시작했다면 자신이 종료하고 기존 테스트 자료·설정을 보존한다. 후보 해시·빌드·migration·운영 적용 시 필요 작업과 코드/DB 복귀 제한만 간결히 기록한다.

## 종료 판정·보고

- 위 합의된 기능의 UI/API/권한/저장·재조회가 실제 STAGING에서 구현된 경우에만 `IMPLEMENTATION=PASS`, `STAGING_VERIFIED=true`. 단순 목업·버튼·테스트 fixture, 메뉴만 존재하는 기능은 PASS가 아니다. 기능 단위로 PASS/FAIL/UNVERIFIED를 구분한다.
- 기술적으로 서로 충돌하거나 별도 사용자·권리·운영 권한을 요구하는 문제는 해당 기능만 안전하게 중단하고 근거를 남기며 다른 승인 기능은 계속 진행한다. **이 경우 전체 기능이 완료되지 않았으므로 전체 PASS로 표시하지 않는다.** 실사용 위험을 숨기거나 기능이 없는 것을 동작한다고 보고하지 않는다.
- 정확도 독립 인증은 기존 `BLOCKED_DATA`, R2는 `DISABLED`, `OPERATING_APPLIED=false`, `DEPLOYMENT_AUTHORIZED=false` 유지. 운영 적용은 별도 사용자 명령으로만 실행한다. commit/push/merge/deploy 및 라이브 운영 데이터 이동·변경을 금지한다.
- STATUS / CHANGED / RULES / TESTED / RISKS 다섯 항목만 보고한다. 변경 파일·source SHA/빌드 SHA, 목표 기능 완료 목록·남은 차단, 실행 명령·exit code·pass count, STAGING 실증 범위, 미실행 검증, 운영 적용에 필요한 최소 사항을 간결하게 기록한다. 완료하면 다음 무관한 기능 작업을 시작하지 않는다.
