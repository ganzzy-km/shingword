# PATCH-BACKUP-001 — S4 새 분석 확인과 백업 적용 분리·재개

## 목표와 이번 승인
기존 외장 백업 후보를 재구현하지 않고 외장 사본의 격리 복원, 검증된 런타임 적용, 60분 자동 복사 활성화까지 마무리한다.

이 지시를 적용하는 것은 기존 apply 명세의 선행조건 한 항목을 명시적으로 개정하는 승인이다.
- 삭제할 의존성: PATCH-ENGINE-001의 실제 계정 새 분석 확인이 완료돼야 백업 적용을 시작할 수 있다는 조건.
- 유지할 조건: 실제 서비스·운영 DB 식별, 기존 데이터 보존, 백업 완료·검증 기록, 볼륨·해시 확인, 복원 권한·잠금·격리, 안전한 중지·재시작, 복귀 수단.

S4 새 분석 미확인은 ENGINE 확인 작업에 그대로 남긴다. 시험 제목 조회 0건을 분석 실행 PASS나 엔진 장애로 바꾸지 않는다. 로그인 우회, 운영 DB 시험 기록 삽입, 기존 실패 상태·횟수 삭제는 승인하지 않는다.

이번 적용 권한은 기존 명세와 동일하다. 검증된 런타임 3개 파일·필요 설정, 최초 격리 복원에 필요한 소유 서비스의 계획된 중지·재시작, 기존 구현의 60분 예약 작업 등록·활성화만 허용한다. 운영 DB 복원·초기화·이전·migration이나 새로운 기능 개발은 금지한다.

## 1. 이미 확보한 근거를 재사용한다
AGENTS.md, ACCEPTANCE.md의 패치 원칙, 기존 apply 명세와 현재 후보 manifest·최신 apply-001 receipt의 필요한 항목만 확인한다.

기존 상태:
- IMPLEMENTATION PASS, 신규 31개·관련 회귀 30개 PASS.
- E:\GeulbitBackups: 지정 볼륨에 암호화 완료본 사본 1개, 재읽기 해시 확인.
- 실제 외장 격리 복원과 자동화 적용 미완료.
- 로컬 백업 생성 24시간, 보관 7일. 정상 종료 추가 백업 없음.

관련 코드·입력·의존성·환경이 같으면 61개 테스트 receipt를 재사용한다. 전체 엔진 검사·57건·24편·build/E2E를 반복하지 않는다.

새 의존성 개정 기록과 실행 결과는 apply-001 아래 새 하위 디렉터리에 추가한다. 과거 Queue·Checkpoint·receipt는 보존하고 기존 승인·최종화 경로를 사용한다. Runner 재설계나 별도 복구 체인은 만들지 않는다.

## 2. 실제 적용 대상만 읽기 전용으로 확인한다
- 운영 서비스의 실행 파일·작업 경로·소유 프로세스·기존 설정으로 실제 사용하는 데이터 루트와 DB를 확인한다. 임의로 찾은 같은 이름의 DB를 대상으로 삼지 않는다.
- 예상 운영 DB: C:\Users\USER\GeulbitData\db\geulbit.sqlite3, schema 0004_user_annotations. 실제 설정·파일 식별과 대조한다. DB가 없을 때 조회 도구가 새 DB를 생성하지 않게 한다.
- 이전 조회 DB와 실제 서비스 DB가 다르면 정확한 경로 불일치를 보고하고 적용을 중단한다. 데이터를 이동·병합하거나 설정을 자동으로 고치지 않는다.
- 서비스와 DB의 일치가 확인되면 지정 시험 글이나 새 분석이 없다는 이유만으로 백업 패치를 중단하지 않는다. 이번에는 시험 글을 다시 생성·검색하지 않는다.
- 운영 S4 파일·기존 배포 기록, 후보 런타임 3개 파일, 변경 전 복귀 사본을 대조한다. 해시·경로는 실제 manifest에서 읽고 추측하지 않는다.
- 현재 외장 볼륨 ID, 전용 폴더, 선택한 외장 사본 SHA와 해당 완료·검증 기록을 대조한다.
- 검증 영수증 없는 다른 로컬 백업은 보존하되 자동 복사 대상으로 승격하지 않는다. 그 파일의 존재만으로 검증된 사본의 처리를 막지 않는다.

HTTPS 200은 접근 가능성 확인일 뿐 인증된 새 분석이나 DB 쓰기 성공의 증거가 아니다. 새 분석 미검증 상태는 끝까지 별도로 기록한다.

## 3. 기존 외장 사본을 실제로 격리 복원한다
1. 현재 서비스의 원래 실행 상태와 진행 중 작업을 기록한다. 기존 lifecycle 절차로 신규 요청을 막고 쓰기·분석 작업이 안전하게 정리된 후 소유 서비스·터널만 중지한다. 강제 종료하지 않는다.
2. 지정한 외장 .gbb를 입력으로 기존 복원 도구를 실행한다. 도구가 로컬 입력을 요구하면 외장 사본을 격리 위치로 복사하고 동일 해시임을 연결해 기록한다. 다른 로컬 백업으로 몰래 대체하지 않는다.
3. 복원 목적지는 운영·테스트 루트와 겹치지 않는 새 격리 디렉터리다. 기존 권한·잠금·복호화·격리·세션 무효화 조건을 유지하고 DB 무결성·외래키·schema·포함 파일을 확인한다.
4. 복원 결과를 운영 DB로 승격하지 않는다. 운영 글·분석·세션·비밀값을 교체하지 않는다. 평문 복원 자료와 비밀값은 Handoff에 넣지 않는다.
5. 실패하면 자동 복사 활성화를 하지 않는다. 운영 데이터가 온전함을 확인한 뒤 이번 점검이 중지한 원래 서비스를 기존 코드로 복구한다. 안전하지 않으면 닫힌 상태와 원인을 보존한다.

## 4. 검증된 후보 적용과 예약 활성화
외장 복원이 통과한 경우에만 기존 manifest의 런타임 3개 파일·최소 설정을 적용한다. 엔진·UI·DB 스키마·Runner는 수정하지 않는다. 테스트 파일은 운영에 배포하지 않는다.

처음에 실행 중이었던 서비스만 기존 방식으로 재시작한다. 사용자가 원래 중지해 놓은 서비스를 임의로 켜지 않는다. 실제 경로·S4 해시·HTTPS·기존 접근 차단·기존 자료 보존을 확인한다. 엔진 새 분석 상태는 별도 미검증으로 남길 수 있다.

기존에 구현한 예약 작업을 승인된 사용자·권한으로 등록한다.
- 주기: 60분. 새 DB 백업 생성이 아니라 완성된 로컬 백업의 누락 사본 확인.
- 실행 파일·cwd·인수·고정 볼륨·중복 실행 방지·PC 및 로그인 조건 확인.
- 비밀번호를 새 평문 파일에 저장하거나 작업 권한을 확대하지 않음.
- 등록된 예약 작업을 한 번 실행하고 실제 종료 결과·이력·다음 실행 시각 확인.
- 미복사 완료본이 있으면 복사·재읽기 해시 검사. 이미 있으면 SKIPPED_EXISTING을 정상 기록하며 사본을 삭제해 복사를 강제로 만들지 않음.
- 정기 복사는 서버·터널을 중지하거나 재기동하지 않아야 함.

HDD 미연결·쓰기 실패 시 로컬 백업과 서비스가 유지되는 기존 테스트 근거를 재사용한다. 실제 장치를 강제로 분리하지 않는다. 수동 실행 한 번을 향후 매시간 성공 보장으로 보고하지 않는다.

## 5. 중단·복귀·종료
다음은 여전히 적용 중단 사유다.
- 실제 서비스·DB·승인 후보 식별 불일치 또는 확인 불가
- 보호 파일의 예상하지 않은 변경
- 외장 장치·완료 기록·해시 불일치, 실제 읽기 오류·복원 실패
- 기존 권한·잠금·격리 보호 위반
- 안전한 서비스 정리·재시작 불가 또는 적용 후 기능 이상

문제가 생기면 이번 패치의 코드·설정·예약 변경만 검증된 이전 상태로 복귀한다. 운영 DB를 과거 백업으로 덮어쓰지 않는다. 기존 자료와 모든 실패 이력을 보존한다. 범위 밖 제품 수정·기대값 완화·새 복구 시스템 개발은 하지 않는다.

E:의 Warning은 미해결로 기록한다. 로컬 원본·백업을 계속 유지하고 외장은 추가 사본 저장소로 사용한다. 작은 검사나 한 사본의 복원으로 장치 전체 또는 다른 PC의 DPAPI 복구까지 보장하지 않는다.

외장 자동 삭제, 사진·경제 게임 변경, 정상 종료 새 백업, 운영 DB 이전, 테스트 DB 생성, R2 활성화, commit/push/merge는 금지한다. 독립 정확도 데이터 부족도 이 백업 패치의 차단 사유로 사용하지 않는다.

최종 성공 시 서로 독립적으로 기록한다.
- IMPLEMENTATION: PASS
- EXTERNAL_BACKUP: VERIFIED_ON_SELECTED_ARCHIVE
- AUTOMATION_APPLIED: true
- ENGINE_POST_DEPLOY_SMOKE: USER_ACTION_REQUIRED 또는 기존 실제 미검증 상태 유지

실제 완료한 항목만 위 상태를 사용한다. 백업 적용 성공으로 S4 새 분석 확인을 PASS 처리하지 않는다.

STATUS / CHANGED / RULES / TESTED / RISKS만 보고한다. 실제 복원 사본 ID·해시, 예약 작업명·주기·실제 실행 결과·다음 실행, 서비스 복구·자료 보존, 재사용한 검사와 남은 엔진 확인을 간단히 적는다. 완료하면 다음 패치를 자동으로 시작하지 않는다.
