## 단일 수정 방식

1. 명사구 자격·주체 선택에는 기존 품사·조사·수식절 검사를 그대로 사용한다. 동일 명사구를 비교하는 내부 키만 분리한다.
2. 이미 검증된 명사구 범위의 정규화 원문 표면형을 키로 사용한다. 첫 명사구 토큰 start부터 마지막 명사구 토큰 end까지 Python 코드포인트 구간을 사용하고 뒤의 주격·보조·목적격 조사는 제외한다. 품사 태그와 명사 내부 토큰 분절은 동일성 키에 넣지 않는다.
3. 전체 명사구 범위를 사용한다. 소유격·복합 명사의 일부를 지우거나 마지막 토큰만 비교하지 않는다. 내부 공백·조사·이름 일부를 임의로 제거하지 않는다. 기존 NFC/LF 정규화 외 별도 광역 정규화는 만들지 않는다.
4. 해당 범위를 확정할 수 없거나 비어 있거나 유효하지 않으면 신규 연결을 만들지 않는다. form 문자열의 임의 결합, 유사도·부분 일치·접두부 매칭으로 대체하지 않는다.
5. 같은 직전 문장, 같은 문단, 기존 작품 범위, 명시적 비인용 선언, 주체 자격 및 모호성 조건은 모두 유지한다. 표면형 일치는 이 조건 안의 국소 재언급 단서일 뿐 작품 전체의 동일 인물 보증이 아니다. 다른 작품으로 같은 이름을 전파하거나 그/그녀를 이름에 연결하지 않는다.
6. 키 생성·소비의 모든 기존 참조가 같은 계약을 사용하도록 한다. 한쪽만 바꾸거나 fallback 병렬 키를 추가하지 않는다. 비교에 공통 작은 순수 함수가 필요하면 동일 structure.py 안에서만 둔다.
7. 실제 Kiwi 출력, 공개 snapshot 스키마, R0/R1, 점수·margin, 출처 정책, 질문 정책, 기존 동작 어휘 목록은 바꾸지 않는다. 서윤·essayId·원문 전체를 하드코딩하지 않는다.
8. 현재 통과한 두 오탐 차단, 18개 국소 대조, 여섯 역할 복구를 보존한다. 이번에는 작품 문맥 귀속과 해석절 경계 규칙 자체를 다시 설계하지 않는다.

## 코드 수정 전 추가할 대조

기존 기대조건은 한 건도 변경하지 않는다. 아래는 별도 DEVELOPMENT_EXPECTATION으로 고정한다.

- 저장된 서윤 재현을 실제 Kiwi로 실행: sentence-2 [22,35)에 EVIDENCE_CANDIDATE, SCOPED_TRANSITIVE_EVENT, CHARACTER_ACTION, WORK_EVENT_REFERENCE 및 actionLemmas=['금지하']가 나와야 한다. 자동 관계 승인까지 요구하지 않는다.
- 키 단위 검사: 같은 유효 원문 명사구에 NNG/NNP 배치만 다른 경우와 1토큰/분할 토큰인 경우 동일 키. 명사구 자격 검사는 우회하지 않는다. 제어 토큰 검사를 실제 Kiwi 실행 결과로 보고하지 않는다.
- 서윤/도윤, 서윤/서윤희, 서윤의 학교/도윤의 학교는 다른 키. 비어 있거나 범위가 잘못된 입력은 매칭되지 않음.
- 다른 작품·다른 문단·비직전 문장은 동일 표면형만으로 이전 작품의 참여자 정보를 상속하지 않음. 새 문장이 자체적으로 갖는 명시적 작품 근거나 기존 독립 역할까지 없애라는 뜻은 아니다.
- 기존 현실 학교·학생회·도서관 오탐 차단과 무관한 앞절의 책임감/자유/의미 차단을 유지한다.
- 실제 작품 내부 학교 사건, 기존 명시적/인접 주체 대조, N03/N08/D03 6개 역할을 유지한다.

비교 키 검사는 동일성의 구현 계약이고 독립 인물 정답이 아니다. 추가 assertion은 신규 단서의 발생 여부와 기존 역할 보존을 구분한다. CLAIM-only 같은 새로운 배타 조건을 만들지 않는다. 문장 전체 역할을 무조건 지우는 테스트는 금지한다.

## 한 후보에서 이어서 검증한다

1. 기존 실패 1건과 새 키 대조부터 실행한다. 이어 기존 최소 30개가 30 PASS인지 확인한다. 실환경 후보 hash와 명령·exit code를 함께 기록한다.
2. 기존 S4 62개 + S3 44개 + 보호 93개 = 199개와 추가 테스트를 최종 후보에서 실행한다. 기존 node ID·기대값·parameter 보존, skip/xfail 없음. 숫자를 맞추기 위해 테스트를 누락하거나 중복 집계하지 않는다.
3. 독립 Read-only Review로 비교 키 변경과 기존 오탐 차단을 함께 확인한다. 수정한 품사·원문 위치·키와 판정 사유를 Trace에 남기되 원문 노출 계약을 유지한다.
4. 기능 조건이 통과하면 같은 후보로 기존 57조건을 1회 재생한다. 승인 16쌍 보존과 설명되지 않은 역할·관계·질문 회귀 0건을 확인한다. S3 과거 PASS를 새 후보의 PASS로 대체하지 않는다.
5. 합성 24편의 두 모드를 기존 명세대로 재평가한다. N08은 후보 검색·출처 정책 실제 도달·거부·화살표·질문을 별도 기록한다. D03 모호성을 자동 승인하지 않는다. NOT_REACHED를 안전성 검사 PASS로 부풀리지 않는다. 합성 정확도 Precision/Recall은 독립 정답이 없으므로 N/A다.
6. 기능·회귀 PASS의 동일 코드 hash를 동결하고 기존 S4 기술 준비를 한 번 실행한다: typecheck, 설정된 lint, production build, 임시 DB의 격리 HTTP·저장/재조회·권한·CSRF, 기존 DOM·방향·Unicode·MATCH_ONLY, S3 대비 30,000자 p50/p95. 기존 측정 계약의 동일 환경·워밍업·반복 횟수와 p95 <= S3×1.5를 따른다. 새 자동화 플랫폼을 만들지 않는다.
7. 실제 원문이 없는 fixture, 브라우저 모바일 화면과 실제 모바일 기기, 실측과 미실측을 분리한다. 독립 인적 데이터 부족 때문에 기술 준비를 생략하지 않는다. 미실행 검사는 PASS로 기록하지 않는다.
8. 모든 해당 Gate와 보호 28개·고정 39개 무결성이 통과하면 기존 승인된 S4 정식 제출 절차를 수행한다. 원본에는 검증된 누적 3파일 patch만 절차에 따라 반영한다. 운영 배포는 하지 않는다.

최소 예상 RED는 구현 전 증거로만 기록한다. 구현 후 필수 실패나 독립 검토 차단이 남으면 해당 후보를 보존하고 중단한다. 이번 추가 1사이클을 초과한 보완·기대값 수정·Runner 변경을 자동 승인하지 않는다. 기술 환경 문제와 알고리즘 회귀는 구분한다.
