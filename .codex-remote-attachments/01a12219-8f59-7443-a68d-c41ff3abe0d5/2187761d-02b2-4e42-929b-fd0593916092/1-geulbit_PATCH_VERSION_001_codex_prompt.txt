# PATCH-VERSION-001 — 글빛 1.0.0 제품 버전 표시

## 목표
사용자 표시 제품 버전을 `글빛 1.0.0`으로 통일한다. 이번 작업은 격리 개발본 수정과 STAGING 검증까지이며 운영 배포는 하지 않는다.

AGENTS.md, docs/automation/ACCEPTANCE.md의 패치 원칙, 최신 PATCH-STAGING-001의 STAGING.md·완료 receipt만 필요한 범위에서 참조한다. S4 운영 적용과 PATCH-BACKUP-001의 최신 변경을 보존하며 과거 후보를 덮어쓰지 않는다.

## 범위·구현
1. 제품 버전 정의 → 실제 표시 소비자 → 관련 테스트 순으로 탐색한다. package.json의 루트 버전과 프론트엔드 표기를 우선 확인하되 저장소 전체나 과거 보고서는 읽지 않는다.
2. 수정 범위는 제품 버전 단일 원본, 직접 연결된 표시부, 필요한 최소 빌드 연결·루트 패키지 메타데이터·관련 테스트다. 실제 파일 목록을 한 번 확정해 기존 패치 계약에 기록한다. 새 Runner나 버전 관리 시스템은 만들지 않는다.
3. 기존 단일 원본을 재사용한다. 없다면 현재 빌드 구조에 맞는 한 곳에만 버전을 정의하고 표시부가 참조하게 한다. 여러 화면에 1.0.0을 따로 하드코딩하지 않는다.
4. 기존 버전 표시 위치를 재사용한다. 전혀 없으면 기존 설정 또는 도움말 영역 한 곳에 `글빛 1.0.0`만 작게 표시한다. 새 화면·메뉴·팝업은 만들지 않는다.
5. `시험 버전`, `공개 베타`, 개인 프로젝트 소개, 정확도 면책·환영 문구를 추가하지 않는다. 기존 저장·분석·오류·권한 안내는 변경하지 않는다.
6. 실제 사용자용 제품 버전만 변경한다. API /v2 경로, geulbit.structure 등 엔진 식별자, 스냅샷·DB 버전, 과거 V2.2/S4 문서·검증 이력은 유지한다. 일괄 문자열 치환을 금지한다.
7. package.json이 제품 버전을 관리한다면 루트 버전만 변경한다. lockfile의 대응 항목이 실제로 있을 때만 최소 동기화한다. 의존성 업데이트·lockfile 전체 재생성은 하지 않는다.

## STAGING 사용
운영 루트: C:\Users\USER\GeulbitData
테스트 루트: C:\Users\USER\GeulbitStagingData
테스트 주소: https://localhost:8786

STAGING.md의 실제 명령과 지원 옵션을 재사용한다. 이번 후보의 코드·빌드가 실제 테스트 서버에 연결됐는지 경로·해시를 확인한다. 이전 후보 화면을 보고 PASS로 처리하지 않는다.

기존 시험 계정을 사용하고 테스트 DB를 초기화하지 않는다. 운영 서버·터널·DB·예약 작업, E:\GeulbitBackups와 GeulbitExternalBackupCopy는 변경하지 않는다. STAGING 전용 인증 경로·비밀값·시험 자료는 운영 배포물에 포함하지 않는다.

## 최소 검증
- 버전 원본과 실제 사용자 표시가 1.0.0으로 일치하는지 관련 테스트로 확인한다. 필요한 작은 검사만 추가한다.
- 프론트엔드를 수정했다면 최종 후보에서 기존 typecheck와 production build를 각각 한 번 실행한다.
- 기존 브라우저 검증 수단으로 STAGING의 실제 버전 표기를 확인한다. 두 테마와 대표 PC·모바일 폭에서 잘림·겹침·콘솔 오류를 검사한다. 새 E2E 시스템은 만들지 않는다.
- 저장된 시험 글·분석 한 건을 다시 열어 기본 화면과 결과 표시가 유지되는지 확인한다. 새 분석 실행이나 정확도 재평가는 요구하지 않는다.
- 이번 승인 변경분 외 S4 엔진·스냅샷·DB·백업 기능·보호 자료가 유지됐는지 확인한다. 새 delta receipt만 남기고 과거 snapshot·증거를 재작성하지 않는다.

기존 엔진 223개, 정식 138개, 57건 재생, 합성 24편, 성능 측정, Google 실계정 검사는 반복하지 않는다. 관련 코드·입력·환경이 같은 검증은 재사용한다.
버전 변경에 직접 필요한 문제는 같은 범위에서 수정하고 최소 실패 검사부터 재실행한다. 다른 기능 결함이나 계약 충돌을 발견하면 정확한 항목만 기록하고 자동으로 범위를 확대하지 않는다.

## 완료·종료
실제 표시·관련 테스트·필요한 빌드가 통과하고 기존 기능·데이터가 보존돼야 완료다. 브라우저 검증을 못 했으면 추정 PASS가 아니라 미검증으로 기록한다.
검증 후 이번에 시작한 테스트 서버만 종료한다. 변경 목록·patch·빌드 해시·파일 복귀 정보를 기존 패치 출력 위치에 보관한다.

이번에는 운영 코드 복사·재시작·배포를 하지 않는다. 공용 자료 전환, 문구 일괄 정리, 튜토리얼, DB migration, commit/push/merge도 제외한다.
S4 운영 새 분석 미확인과 독립 정확도 BLOCKED_DATA는 별도 유지하며 이번 작업의 선행조건으로 삼지 않는다. R2는 DISABLED로 유지한다.

STATUS / CHANGED / RULES / TESTED / RISKS만 보고한다.
STATUS에는 IMPLEMENTATION, DISPLAY_VERSION, STAGING_VERIFIED, OPERATING_APPLIED를 구분한다.
성공 시 DISPLAY_VERSION=1.0.0, STAGING_VERIFIED=true, OPERATING_APPLIED=false다.
TESTED에는 명령·exit code·실제 확인 화면과 재사용 증거를 구분한다.
완료 즉시 종료하며 PATCH-LIB-001은 자동 시작하지 않는다.
