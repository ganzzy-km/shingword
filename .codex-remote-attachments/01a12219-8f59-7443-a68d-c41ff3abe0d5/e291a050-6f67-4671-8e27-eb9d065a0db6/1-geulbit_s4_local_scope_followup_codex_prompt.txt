# 글빛 V2.2 — S4 보완 계약 v3: 작품 주체와 해석절의 단서 범위 제한

## 목표와 우선순위

기존 S4 계약 v2와 배포 후보 기술 검증 명세를 재사용한다. 이번 추가 명세는 남은 두 오탐의 수정 범위와 추가 후보 보완 권한만 정의한다. 이전 성공 조건을 낮추지 않는다.

여섯 역할 복구를 유지하면서 다른 문장·절의 작품 문맥과 개념어를 끌어오는 신규 역할 오탐을 제거한다. 승인 수를 늘리거나 R2를 구현하는 작업이 아니다.

AGENTS.md, 현재 S4 계약, 최신 Handoff의 아래 부분만 읽는다.
- checkpoint.json과 final-read-only-review.json
- final-blocker-reproductions.json의 두 입력·before/after·관련 Kiwi 토큰
- S4.patch 중 analyze_structure의 신규 역할 부분
- test-expectations-freeze-v5.json의 기존 목표·대조
- N08-stage-clarification.json

과거 Runner 복구·S2 진단·S3 개발을 반복하지 않는다.

## 2. 두 개의 확인된 결함

A. UNRELATED_SCHOOL_REGULATION
입력:
소설 「가상 기록」에서 서윤은 외롭다. 내가 다니는 학교는 휴대전화 사용을 금지한다.

원본 S3의 sentence-2 역할은 없다. 실패 후보는 [22,47)에 SCOPED_TRANSITIVE_EVENT, CHARACTER_ACTION, WORK_EVENT_REFERENCE와 EVIDENCE_CANDIDATE를 추가한다.
원인은 literary_context가 같은 문단의 작품 선언을 승계하고 report_subject가 문장 어디든 명사·대명사+조사만 있으면 통과시키는 것이다. 그 주체가 해당 작품의 사건 주체라는 연결이 없다.

B. UNSCOPED_INTERPRETATION_NOUN
입력:
소설 「가상 기록」에서 책임감을 설명한 뒤 화면은 음성 합성 장치에서 나온다고 볼 수 있다.

원본 S3의 역할은 없다. 실패 후보는 [0,51)에 LITERARY_INFERENTIAL_VIEW와 CLAIM_CANDIDATE를 추가한다.
원인은 문장 전체 nouns의 책임감을 뒤의 추론 서술에 사용한 것이다. 실제 추론 대상은 화면, 직접 출발점은 음성 합성 장치다. 책임감은 앞의 설명 절에 속한다.

이들은 신규 역할 후보 오탐이다. 관계·화살표·질문 오승인까지 재현한 것으로 확대 보고하지 않는다.

## 3. 구현 규칙

공통:
- 신규 S4 역할 경로의 단서 사용 범위만 좁힌다. 기존 독립 claimSignals/evidenceTypes를 전역 필터로 삭제하지 않는다.
- 기존 Kiwi 토큰·span·문장 정보를 재사용한다. Kiwi가 완전한 의존구문 트리를 제공한다고 가정하지 않는다.
- 문장·작품명·essayId를 하드코딩하거나 학교/화면/장치/책임감 같은 금칙어로 반례를 막지 않는다.
- 같은 문단, 고유명사 품사, 임의의 주어 조사만으로 작품 귀속을 확정하지 않는다.
- 기존 점수·임계값·R1·출처 정책·질문·표시·스냅샷 계약과 공용 ACTION_LEMMAS는 유지한다.

A. 신규 사건 역할:
- 대상 행동/상태에 연결되는 실제 주어·대상 구간을 확인한다. 수식절 안의 주어를 중심 행동 주어로 잘못 쓰지 않는다.
- 같은 문장의 명시적인 작품 범위 또는 국소적인 인물·사건 재지칭 등 실제 작품 연결 앵커가 있을 때만 새 작품 사건 단서를 추가한다. 상속된 work_frame 하나만으로 통과시키지 않는다.
- 앞 문장의 작품 인물과 연결되지 않는 필자의 학교·현실 규정에 작품 사건 단서를 전파하지 않는다. 반대로 작품 내부의 학교·기관이 명시된 사건은 명사가 학교라는 이유로 차단하지 않는다.
- N03의 아내 재언급, N08의 동이 행동, D03의 인물과 그 명령 재지칭을 실제 토큰·인접 문맥으로 보존한다. 인물명·가족 명사를 문서 전체에 전파하지 않는다.
- 연결이 모호하면 이 신규 경로에서는 승격하지 않는다. 이것을 사실성이나 출처의 독립 검증으로 표현하지 않는다.

B. 신규 추론 주장 역할:
- LITERARY_INFERENTIAL_VIEW는 추론 대상 절과 그 서술어의 직접 논항에서 해석 단서를 찾아야 한다.
- 우선 현재 정상 목표인 작품에 귀속된 대상 + 해석 개념에서 + 나온다고 볼 수 있다 구조의 직접 연결을 검증한다. 앞절의 개념어를 빌려오거나 전체 명사 집합의 any/intersection만 사용하지 않는다.
- ‘책임감을 설명한 뒤’ 같은 배경절, 인용, 별도 주어의 수식절에서 얻은 개념은 뒤의 ‘장치에서 나온다’에 사용할 수 없다.
- 모든 EC나 마지막 JX에서 무조건 자르는 방식도 금지한다. 추론 명제 내부의 연결어미와 ‘-다고 볼 수 있다’ 종결 사슬을 구별한다.
- N08의 ‘김첨지의 돌봄은 가족을 향한 책임감에서 나온다고 볼 수 있다’와 이미 동결된 정상 대조를 유지한다.
- 지원되는 국소 형태를 넘어서는 문장은 이 신규 경로에서 보류한다. 범용 의미 파서나 새 사전으로 확장하지 않는다.

## 4. 코드 수정 전에 추가 대조를 고정한다

기존 S4 44개, 개정된 S3 44개, 보호 93개의 의미적 기대값을 유지한다. 아래는 추가 DEVELOPMENT_EXPECTATION이며 인적 정답이 아니다.

필수 반례:
- 위 A/B 원문에서 해당 신규 cue와 잘못 추가된 역할이 없어야 한다.
- A의 실제 주체를 학생회·도서관 등으로 바꾸어도 작품 연결이 없으면 같은 신규 승격이 없어야 한다.
- B에서 앞절의 책임감을 자유·의미로 바꾸거나 앞절을 제거해도 무관한 뒤 추론절의 신규 cue는 생기지 않아야 한다.

필수 정상·대조:
- ‘소설 「가상 기록」에서 학교는 학생의 외출을 금지한다.’는 명시적 작품 사건 단서를 유지한다. 학교라는 단어 자체를 차단하지 않는다.
- ‘소설 「가상 기록」에서 서윤은 외롭다. 서윤은 입장을 금지한다.’는 명시적으로 연결된 주체를 보존한다. 무조건 매 문장 작품명을 요구하지 않는다.
- N03/N08/D03의 여섯 역할과 두 모드의 기존 ID/span을 보존한다.
- N08의 정상 추론 대상 절은 앞에 무관한 배경절을 추가해도 그 직접 해석 논항을 잃지 않는다.
- 인용문이나 기존 독립 단서 때문에 이미 있던 역할은 보존한다. 신규 cue 없음 검사를 모든 역할 없음 검사로 일괄 바꾸지 않는다.

각 추가 조건은 기준 S3 동작, 필요한 신규 단서, 금지 단서와 근거를 기록하고 구현 전에 검토한다. 추가 반례의 예상 RED는 구현 전 정상이다. 출력에 맞춰 기존 기대값을 바꾸지 않는다. 조건이 충돌하면 그 항목만 명시하고 자동 개정하지 않는다.

## 5. 같은 후보에서 검증 후 기술 준비까지 진행한다

1. 두 반례와 정상 대조, 여섯 역할의 최소 테스트부터 수행한다.
2. 통과하면 기존 S4 44개+추가 대조, S3 44개, 보호 93개를 최종 후보에서 묶어 실행한다. 기존 181개 node ID의 누락·skip·xfail 없이 신규 테스트 수를 구분한다.
3. 새 hash에 대한 독립 Read-only Review에서 두 반례와 범위 오염 대조를 확인한다. 알려진 기능 실패를 먼저 해소하고 57건/빌드를 반복하지 않는다.
4. 통과한 후보로 기존 57조건을 1회 재생한다. 승인 16쌍 보존과 역할·관계·질문의 설명되지 않은 회귀 0건을 확인한다. 원본에 증거가 보존됐다는 사실로 새 후보 검증을 대신하지 않는다.
5. 기존 도구로 합성 24편의 두 모드를 각 2회 재평가한다. 현재 입력에서의 기대조건·결정성·새 오탐을 기록한다. Precision/Recall은 독립 라벨이 없으므로 N/A다. R2 runtime은 계속 DISABLED다.
6. N08을 실제 경로로 확인한다. 연결 모드는 두 출처를 식별하고 해당 쌍을 REJECTED/EXPLICIT_DIFFERENT_WORK_IDS로 처리하며 화살표·확정 질문을 만들지 않아야 한다. STANDALONE은 RETRIEVED와 SOURCE_POLICY_NOT_REACHED를 구분한다. 단위 함수 직접 호출을 전체 경로 PASS로 보고하지 않는다.
7. P06/D01의 기존 REVIEW, D03 복수 대상 모호성, N07/P08 정상 비교와 질문 안전성을 유지한다.
8. 기능 조건 통과 후 동일 코드 hash를 동결하고 기존 S4 명세의 기술 준비를 1회 수행한다: typecheck, 설정된 lint, production build, 임시 DB의 격리 HTTP·저장/재조회·권한·CSRF, 기존 브라우저 DOM·화살표·Unicode·MATCH_ONLY 검사, 동일 환경 S3 대비 30,000자 p50/p95. p95 <= S3×1.5를 적용하고 실제 원문 없는 조건·실기기 미검증을 구분한다.
9. Scope·보호28·고정39·독립 검토와 기존 S4 최종 Gate가 모두 통과한 정확한 후보만 최초 정식 제출한다. 기술 검사 실패 시 범위 밖 코드나 설정을 수정하지 않고 미완료 검사와 원인을 보고한다.

독립 인적 데이터가 없다는 사실은 합성 검증과 기술 준비를 중단할 이유가 아니다. 그러나 일반 정확도 인증이나 배포 승인으로 바꾸지도 않는다.

## 종료 규칙

추가 보완 1사이클 한도를 소진하거나 필수 조건에 실패하면 후보와 원인을 보존하고 중단한다. 정식 제출 0회를 초기화하거나 제품에 먼저 반영하지 않는다. Runner 추가 개발·범위 확장·기대값 완화는 하지 않는다.

운영 DB·서버·배포 변경, Golden/Baseline 수정, 새 AI/의미 모델, R2 활성화, commit/push/merge/deploy를 금지한다. 실행 산출물을 위한 임시 DB·격리 서버만 기존 S4 권한으로 사용한다.

STATUS / CHANGED / RULES / TESTED / RISKS만 보고한다.
STATUS에서는 다음을 구분한다.
- IMPLEMENTATION
- TECHNICAL_PREP
- ACCURACY_CERTIFICATION: BLOCKED_DATA
- DEPLOYMENT_AUTHORIZED: false

여섯 역할 6/6·12조건, 반례 A/B와 추가 대조, 기존181+신규 테스트, 57건·16쌍, 합성24 결과, N08 실제 단계, 기술 검사 결과와 미측정 항목을 적는다. 후보 보완 과거2회·추가1회와 정식 제출 횟수를 분리한다. 전체 정확도를 보장한다고 표현하지 않는다. 완료되면 즉시 종료한다.
