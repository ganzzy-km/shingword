0. 먼저 읽을 핵심

S4는 별도의 새 AI 모델이나 전면 재작성 엔진이 아니다. 기존 Kiwi·로컬 규칙 기반 분석에 근거 선행, 직접 지시 R1, 출처 정책, 역할 탐지 보완을 누적한 개발 기준이다.
개발 작업본 채택과 운영 서버 적용은 다르다. 최종 운영 프로세스가 이 코드를 사용해 새 분석을 생성하는 것까지 확인해야 한다.
R2 설명 매개 모듈은 실험용이다. S4 적용에 함께 활성화하지 않는다.
역할 후보의 발견, 관계 후보의 검색, 관계 승인, 화면 표시, 질문 생성은 서로 다른 단계다. 한 단계의 성공을 다음 단계의 성공으로 계산하지 않는다.
주장 역할과 근거 역할은 같은 문장에 함께 존재할 수 있다. 신규 CLAIM을 추가하면서 기존 EVIDENCE를 무조건 제거하지 않는다.
기존 분석 결과·사용자 글·원작품 판본·소유권은 보존한다. 과거 결과를 새 엔진 결과로 조용히 덮어쓰지 않는다.
전체 문서를 반복해서 읽지 않는다. 최초에는 0~3절을 읽고 문제 발생 시 해당 절과 실제 symbol만 확인한다.

2. 개발 목표와 비목표

목적은 학생이 자기 에세이의 주장, 제시한 근거, 연결 단서와 수정할 부분을 확인하는 데 도움을 주는 것이다. 교사 피드백을 반영하는 학습 목적과 자동 성적 산정 기능을 혼동하지 않는다. 교사 피드백을 자동 학습하는 기능이 구현됐다고 이 문서는 주장하지 않는다.

구현 목표:
- 주장·근거 후보를 탐지한다. 역할이 겹치는 문장을 허용한다.
- 근거가 주장보다 앞에 있거나 뒤에 있는 텍스트 순서를 처리한다.
- 명시적 지시가 충분하면 공통어가 없는 구조적 관계도 R1으로 검토한다.
- 작품과 판본을 구분하고 확인된 교차 작품 오연결을 차단한다.
- 불확실한 관계를 확정 화살표나 확정적 질문으로 승격하지 않는다.
- S3의 '~로 읽힌다' 및 S4의 남은 역할 누락을 좁은 문법 범위에서 보완한다.
- 같은 입력·규칙·선택 판본·환경의 결과가 재현되도록 한다.
- 과거 저장 결과, Unicode 위치, 사용자 권한과 원문 제한을 유지한다.

비목표:
- 문학 해석의 진위, 교사 점수, 성적 향상 보장.
- 모든 어휘·장르·암시적 의미 관계의 완전한 이해.
- R2 실제 활성화, 새 모델·개념 사전·의존구문 분석기 도입.
- 이번 패치에서 UI 개편, 튜토리얼, 공용 자료 전환, 제품 버전 표기를 함께 구현하는 것.

5. 핵심 판정 계약

5.1 역할
roleCandidates는 각 문장에 대한 기록이다. roles가 빈 문장도 포함된다. 'roleCandidates에 있다'와 'CLAIM/EVIDENCE 역할이 있다'를 구분한다.
CLAIM과 EVIDENCE는 독립적으로 구성되며 같은 문장에 둘 다 존재할 수 있다.
S4는 기존 관측을 보존하며 다음 좁은 경로를 추가한다.
- P06·D01: '이 행동은 ... 과정/변화로 읽힌다'의 해석 주장.
- N03: '이 장면은 ... 비극을 보여준다'의 주장, '아내는 이미 숨져 있다'의 사건 상태 근거.
- N08: '책임감에서 나온다고 볼 수 있다'의 국소 추론 주장과 '업어 건너게 하는' 장면 근거.
- D03: 작품 범위에서 매장을 금지하거나 명령을 어기고 의무를 행하는 근거.
N03·N08·D03의 목표는 고유 역할 6개이고 두 모드에서 12개 역할 assertion이다. 고유 관계 12개나 독립 평가 12편을 뜻하지 않는다.

5.2 S3/S4의 국소 문맥 보호
'의미·경험'이 문장 어디에 있다는 사실만으로 읽기 절차를 해석 주장으로 만들지 않는다. 마지막 수식절과 직접 대상의 범위를 확인한다.
'책임감을 설명한 뒤 화면은 장치에서 나온다고 볼 수 있다'에서 앞절의 개념을 뒤 추론에 사용하지 않는다.
작품명이 앞에 나왔다는 이유만으로 '내가 다니는 학교는 휴대전화 사용을 금지한다'를 작품 사건으로 처리하지 않는다.
주체·직접 대상·작품의 국소 범위를 확인한다. 동일 인물이라는 무제한 추정이나 일반 대명사의 자동 인물 매핑을 추가하지 않는다.
명사구 자격에는 품사·조사를 사용하고 동일성 비교에는 검증된 전체 원문 표면형을 사용한다. 같은 '서윤'의 NNP/NNG 분절 차이로 동일 표기를 놓치지 않는다. 부분 문자열, 소유격, 공백을 제거해 서로 다른 명사구를 합치지도 않는다.

5.3 R0 관계 검색과 승인
기존 규칙 기반 경로를 편의상 R0라고 부른다. 구현된 모든 관계가 새 hard gate 방식으로 대체된 것은 아니다.
[E2]에서는 주제어별 주장 posting 상한 128, 국소 문장 창 앞뒤 12, 문단 차이 2 제한과 별도 설명 조건이 존재한다.
R0 점수는 공유 명사 수 상한, 같은 문단, 가까운 거리, 연결 표현, 제한된 작품 문맥 단서의 합이다. 점수는 확률이 아니다.
4점 이상은 R0 내부 후보 판정의 한 조건이고 승인된 R0 관계는 7점 이상이다. 같은 방향 후보의 기존 2점 차이 경쟁 기준을 유지한다.
주장 선행과 근거 선행의 경쟁 집합을 분리한다. 반대 방향 후보가 생겼다는 이유로 기존 정상 관계를 제거하지 않는다.
일반 역방향 출력은 보수적으로 제한돼 있다. 기존 점수나 margin을 낮춰 관계 수를 늘리지 않는다.
원작품 인용 일치나 같은 workId를 새 가산점으로 더하지 않는다. 기존 R0의 제한적인 scoped_work 항목이 존재한다는 구현 사실과 이 원칙을 혼동하지 않는다.

5.4 R1 직접 지시
기존 구현은 문두의 '이 행동은', '이 장면은', '이 발언은'을 실제 Kiwi 토큰과 위치로 확인한다. 과거 설계 초안에 적힌 모든 지시어가 구현됐다고 가정하지 않는다.
같은 문단의 직전 근거와 뒤 주장을 대상으로 한다. 공통 명사, 과거형, 고유명사 주어가 절대 필수는 아니다.
복수 지시, 원거리 지시, 직전 문장의 복수 사건, 앞선 경쟁 근거, 대상 종류 불명확, 작품 충돌은 보류 또는 후속 출처 정책 대상으로 남긴다.
R1은 어휘 점수·방향별 점수 경쟁과 독립된 경로다. R0의 7점 기준을 모든 R1에 새로 적용하지 않는다.
'이 선택'을 S4가 자동으로 R1 승인해야 한다는 기대값을 만들지 않는다. D03의 모호한 지시를 강제 승인하지 않는다.
논증 방향은 EVIDENCE_TO_CLAIM이며 textOrder는 CLAIM_FIRST/EVIDENCE_FIRST로 별도 기록한다.

5.5 출처 정책
workId와 revisionId를 구분한다. 다른 revisionId가 곧 다른 작품은 아니다.
EXPLICIT, INFERRED, UNKNOWN을 유지한다. 미확인을 충돌로 단정하지 않는다.
두 작품이 EXPLICIT이고 서로 다르며 정당한 비교 문맥이 없으면 EXPLICIT_DIFFERENT_WORK_IDS로 거부한다.
'비교적', '비교적인'의 부분 문자열을 비교 근거로 쓰지 않는다. 실제 비교 동작·대상과 인용문 밖의 문맥을 확인한다.
등록된 제목의 '에서는' 경계를 처리하되 긴 다른 제목이나 일반 단어의 접두부를 잘못 식별하지 않는다.
명시적 비교는 출처 거부의 예외를 검토할 단서이지 관계 자동 승인권이 아니다.
이미 발생한 R1 보류를 등록된 동일 작품·비교 정보로 해소하는 제한된 예외는 출처 guard만 대상으로 한다. 복수 사건 등 문법·모호성 guard까지 해제하지 않는다.
관계가 생성되지 않으면 source_relation_policy가 호출되지 않을 수 있다. '화살표 없음'을 출처 거부 성공으로 계산하지 않는다.

5.6 화면·질문·불변 결과
SUFFICIENT_SIGNALS는 관찰된 구조 단서가 충분하다는 뜻이다. 해석이 옳거나 점수를 보장한다는 뜻이 아니다.
REQUIRES_REVIEW는 확정 화살표에 포함하지 않는다. REJECTED도 확정 관계나 이를 전제한 질문에 사용하지 않는다.
REVIEW가 있다는 이유로 일반 질문 전체를 없애지 않는다. 안전한 일반/조건부 질문과 확정적 연결 질문을 구분한다.
원문 접근 제한과 분석 대조 허용은 다르다. MATCH_ONLY 전문을 JSON, 질문, 미리보기, 다운로드/PDF, 진단 로그에 노출시키지 않는다.
입력 본문은 기존 NFC/LF 정규화와 코드포인트 반열린 구간 [start,end)를 따른다. JS UTF-16 인덱스와 혼용하지 않는다.
분석 결과는 입력 글 버전·불변 원작품 revision·규칙 설정에 귀속된다. 본문 수정 시 과거 결과를 삭제·재작성하지 않고 기존 STALE 계약을 적용한다.
사용자 표시 제품 버전 1.0.0과 내부 엔진·스냅샷·DB 버전은 별개다.

5.7 중요한 실제 버전 조건
[E2]에서 STRUCTURE_VERSION은 geulbit.structure/8이다.
출처 정책이 관찰 가능한 결정을 바꾸거나 이전 작품명 충돌을 해소하면 관계에 sourceDecision/anchorAssessment가 남고 결과는 /9를 사용한다. 순전히 중립인 출처 준비에서는 해당 부가 필드를 제거하고 /8을 유지한다.
따라서 S4가 로드됐다는 사실을 응답의 /8 또는 /9 하나로 판정하지 않는다. 운영 파일 해시·프로세스 경로·실제 새 분석 결과를 함께 확인한다.
S4 추가 결함 수정으로 코드가 바뀌면 원본 S4 SHA를 새 파일에 주장하지 않는다. S4 기반 보정 후보로 새 해시를 기록한다. 결과 계약이 달라지면 기존 버전 관리 방식으로 호환성 정보를 함께 검토한다.

6. 알려진 오류와 올바른 복구 방향

- CLAIM-only 테스트가 기존 EVIDENCE와 충돌: 역할 추가와 보존을 함께 검사한다. 기존 근거를 삭제해 통과시키지 않는다.
- S3의 N08 역할 없음 검사와 S4 역할 복구 충돌: 이미 승인된 S4 테스트 개정을 사용한다. 옛 단계 한정 기대값으로 되돌리지 않는다.
- 4점/6점 REVIEW인데 화살표 1개를 요구: 기존 REVIEW 음성 사례와 8점 승인 양성 사례를 함께 검사한다. 임계값을 내리거나 빈 관계만으로 PASS하지 않는다.
- STALE 문구 치환이 no-op: 실제 relation endpoint span을 수정하고 editedBody가 달라졌는지 확인한다. 다른 화면 PASS로 대체하지 않는다.
- 같은 인물의 품사 차이: 명사구 자격과 표면형 동일성을 분리한다. 이름 하드코딩이나 Kiwi 출력 조작 금지.
- R2 후보 0건: 역할/앵커/검색의 최초 미도달 지점을 구분한다. 승인을 늘리려고 범위를 무작정 넓히지 않는다.
- 운영에서 옛 엔진 실행: 코드 복사 여부뿐 아니라 서비스 명령·실행 루트·재시작·실제 새 분석 경로를 확인한다.

9. 이번 적용 패치의 경계와 최소 성공 기준

이 항목은 현재 사용자 요청에 따른 실행 기준이다. 과거 '운영 적용 금지' 기록은 당시 작업의 상태로 보존한다. 새 프롬프트를 실행하라는 지시는 해당 S4 적용의 제한된 승인이며 과거 receipt를 PASS로 위조하는 권한은 아니다.

성공은 다음을 모두 뜻한다.
- 검증된 S4 또는 S4 기반의 최소 보정 후보가 실제 대상 서비스에 반영됨.
- 실제 실행 경로·프로세스와 승인 파일 해시가 일치함.
- 실제 API로 생성한 새 분석에서 목표 역할·관계 상태·글 버전이 예상대로 확인됨.
- 저장·재조회·수정 후 재분석·STALE·권한·제한 원문 보호가 유지됨.
- 기존 글과 과거 결과가 보존되며 실패 시 안전하게 이전 버전으로 돌아갈 수 있음.
- R2 비활성, 범위 밖 UI·공용 자료·계정 정책 변경 없음.

독립 인적 데이터 부족은 이 지인 시험 적용의 차단 조건이 아니다. 정확도 인증 상태는 그대로 미완료로 기록한다.
기본 로그인·저장·자료 권한·데이터 무결성 실패, 제한 원문 노출, 지속적인 서버 장애는 적용 전에 해결한다. 알려진 일부 관계 누락이나 느리지만 완료되는 요청을 이유로 전체 정확도 연구를 재개하지 않는다.

10. 자료를 읽고 수정할 때의 순서

실패 입력과 현재 결과 확인 -> 최초 문제 단계 확인 -> 관련 symbol과 직접 호출부 -> 기존 정상/반례 테스트 -> 최소 수정 -> 실패 테스트 재실행 -> 영향 범위 검사 -> 운영 적용과 실제 결과 확인.

데이터 이동·DB 전환이 필요하면 현재 버전을 실제 확인한다. 과거 0004/0005 기록을 현재 상태로 단정하지 않는다. 우선 스키마 변경 없는 적용을 사용한다. 기존 검증된 마이그레이션이 정말 필요한 경우에만 복사본에서 확인하고 백업·복원 경로를 갖춘 뒤 처리한다. 새 migration을 즉석에서 만들지 않는다.

새 문학 분석 구조, 무제한 복구 Runner, 다른 제품 기능을 이 작업에 추가하지 않는다. 본 문서만으로 코드가 자동 배포된 것은 아니며 별도 패치 프롬프트를 실제 Codex 환경에서 실행해야 한다.
